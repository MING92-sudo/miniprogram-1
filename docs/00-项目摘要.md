## 1. 系统组成（实测计数）

| 部分 | 位置 | 现状 |
|---|---|---|
| 微信小程序 | 仓库根目录 | 原生小程序，**46 页** = 主包 20 + 4 子包（pkg-handover 8 / pkg-maintenance 7 / pkg-admin 7 / pkg-client 4）；无原生 tabBar（custom-tabbar 菜单驱动）；根 `services/` 11 个共享模块 + 分包私有服务 2 个；`mock/server.js` 128 条路由 |
| 后端 | `backend/` | Java 17 + Spring Boot 3.3.4 + MyBatis-Plus + MySQL 8 + Flyway **V1—V67**（65 个迁移文件，V30/V32 缺号）+ JWT/BCrypt；947 个 @Test |
| 管理端 | `admin/` | Vue3 + Vite + **自建组件库**（`admin/src/ui/`，Element Plus 已移除，无演示数据）；32 个视图（另含 dev/ComponentsGallery 开发态工具页） |
| 脚本 | `scripts/` | 平台联调 PowerShell（`*.ps1`）+ 派单/模板回归 Node 脚本（`verify-dispatch.js` / `verify-templates.js`） |

分层：页面 → `services/*` → `utils/request.js`（唯一请求封装：Bearer、`X-Idempotency-Key`、401、callContainer/wx.request 分流）；离线走 `utils/offline.js`（快照 + 补传队列）。生产默认 `wx.cloud.callContainer`，上传因 callContainer 只收 JSON 仍走 `wx.uploadFile`，两条链路统一 `{code, message, data}`。

## 2. 业务闭环

```
定时派单（每日 09:00 主扫 + 每 13 分钟兜底）→ 区域池发布（PENDING，不带人）
→ 主维保到场签到即原子认领（GPS 围栏）→ 配合人员双人动态码签到
→ 作业清单（周期项可"本次不执行"；关键项强制照片）
→ 签退（≥30 分钟、双人签名、异常项 S0—S7）→ 冻结快照并自动上报平台 2.6
→ 使用单位（客户）签字确认 → 管理端归档 / PDF 导出
```

## 3. 关键业务不变量（改动前必读）

1. **工单归属（2026-11-21 区域抢单池）**：派单一律不写主/配合人，落 `work_order.region_id` 区域快照（电梯事后改区域不回溯在池工单），PENDING=待接单；**主维保签到即原子认领**（落败 `1003` 回显认领人；登录人无平台ID `422` 零副作用）。工单读写统一经 `scopeOrders`/`requireOrderScope`：已认领按认领人/配合人 platformId，未认领按池谓词（持平台ID + 区域匹配）放行，管理角色不限；越权一律 `1403` 且零副作用。电梯写谓词按在途工单认领关系。绕过归属校验 = 代签到/代签退 = 向监管平台写虚假数据（Blocker）。
2. **签到**：定位必填（缺 `422`），严禁伪造坐标；主维保按 Haversine 三级阈值（电梯级→品种级→全局）拦截 `1001`；**配合人免距离围栏**（`geoStatus=ASSISTANT_EXEMPT`，定位照采；身份比对先于动态码消费）；电梯无坐标时主维保只留痕 `UNKNOWN` 不拦截，并以主维保定位回填 `SELF_COLLECTED`，自回填起即为围栏基准、存量立即生效无豁免。主/配合分别留痕，重复签到 `1003`。
3. **双人动态码**：`HMAC(密钥, 工单ID|时间步长)`，5 秒步长、60 秒有效、绑定工单；配合人签到用 `consumeDynamicCodeIfUnused` 原子消费；`/dynamic-code/verify` 只验不消费；校验/消费必须先于任何写操作。
4. **清单与签退**：周期项 `notInThisRun=true` 不计必填；关键项且 `photoRequired` 至少 1 张照片（`NA` 除外）；签退要求 `PROCESSING`、作业 ≥30 分钟（`APP_WORK_DURATION_MINUTES` / 前端 `minWorkDurationMinutes` 双保险）、主维保签名必填；**池化新单双人恒必填（D8）**——`regionId` 非空或 `claimedViaPool=true` 的工单缺配合人/缺任一签名一律 `422`；存量在途单（无区域快照无认领标记）维持"有配合人时双签名"旧口径，但最终 2.6 快照仍须补配合人平台 ID。异常项必须显式 S0—S7（S0 合法）；仅当无异常项时才自动补 S0。
5. **上报快照**：签退时冻结检查项与 `reportPayload` 快照，2.6 用快照上报；失败只标记状态，仅逐条人工重报。签退冻结与人工重报均经 `ReportPayloadValidator` 校验 19 个必填项及日期、手机号、类别/隐患码格式；主/配合人平台 ID 必须唯一关联一名手机号完整的员工，V66 以 `uk_employee_platform_id` 唯一索引兜底，空 ID 统一存 NULL。
6. **派单与建档路径**：只由定时任务驱动派单，读接口不触发派单；到期基线 = 最近一次同类型已完成维保 → 首次维保（最早 DONE 签退）→ 建档 `lastMaintenanceAt`；**建档即排期**（`nextMaintenanceDate` = 基线 + intervalDays，缺省 15）；同项目同日到期一次全派。**建档仅两条路径**：外接梯由管理端电梯台账直建（`archive_source=0`）并立即进入排期；自装梯经安装移交查验、签字、确认后归档建梯（`archive_source=1`）并排首保；旧外接建档状态机及首保 +3 天特例已由 V65 移除。管理端直建/编辑保存后自动对该梯做一次 2.7 查询回填（查询接口，凭证未配置/失败不阻断保存，返回行标注 `platformSync`: OK/NO_MATCH/SKIPPED/FAILED）；电梯未手动指定使用单位时，按 2.7 返回的平台主体ID自动挂接本地使用单位档案。新移交单起草即校验使用单位及监督检验报告、安装质量证明文件、维护使用说明书并进入内部审核，客户端不得传 `elevatorId`；注册字段可空，确认归档时以出厂编号等一次 2.7 查询，唯一匹配后回填电梯编码/注册代码/设备代码并建挡排期，0 条/多条/他梯/冲突均保持待确认且零副作用，V67 以 `uk_elevator_code`、`uk_elevator_reg_code`、`uk_elevator_device_code` 防重。管理端可"退回池"（`POST /admin/orders/{id}/release-to-pool`，DONE `422`，审计先行 + `status<>'DONE'` 守卫）。
7. **文件**：配置 COS 时 COS 为唯一持久化源，本地磁盘是写穿/写回缓存（读本地→未命中回源 COS→写回）；`GET /files/{id}` 校验 `?s=` 时效签名；所有读路径经 `FileStorageService.urlOf` 重签；数据库只存不带签名的稳定 URL。
8. **工单号**：只经 `OrderNoIssuer` 发号；唯一键冲突重试时重新统计当日计数取 +1，不得用重试次数当偏移。
9. **账号权限**：一手机号 = 一账号 = 同时刻单会话（`em_token`，登录即清旧会话）；多角色权限取并集、数据范围逐角色判定（写绝不扩大）；`activeWorkspace` 决定工作台渲染。登录只有 `POST /auth/login` 一个入口，按账号自动识别员工/客户。**客户主体**（角色 CUSTOMER）三层收敛：路由白名单（仅 `/unit/**` + 自身账号端点 + `GET /elevators*`、`GET /files/*`）；签字状态门禁（可签 = 唯一 PENDING_CLIENT_SIGNATURE + confirmStatus=PENDING，条件更新先签为准，签字/拒签不触发 2.6）；字段白名单 `toClientMap`（禁返 reportPayload/shareToken/平台ID/refuseReason 等）。

### 4.1 实测结论表（优先级高于规范 V1.5 原文）

| # | 事项 | 规范原文 | **实测结论** |
|---|---|---|---|
| 1 | 2.1 登录方式 | POST + Body | 🔴 **GET + URL 查询串**（POST 恒返回 `{"code":500,"message":"操作失败!"}`） |

| 4 | 2.3/2.4 文件 | multipart（携带文件时）；contractFile "选填" | 🔴 **必须 multipart + 文件**：2.3 `contractFile` 必传（无文件 HTTP 400，form 全 500）、2.4 `certificateFile` 建立时必传（500 明示） |

## 5. 部署与配置

- **云托管**：根 `Dockerfile` 多阶段构建（Node 20 构建 admin → Maven 打包后端 → JRE 17 Alpine），容器端口 80，健康检查 `GET /health`；小程序走 `wx.cloud.callContainer`（`config/index.js` 的 `cloud.env/service`），上传须配 uploadFile 合法域名。
- **本地后端**：MySQL 8（`backend/scripts/local-db-init.sql` 建库，utf8mb4/utf8mb4_general_ci）；根目录 `.env` 配 `DB_*` 与 `JWT_SECRET`（≥32 字节，无默认值，缺失即启动失败）；从**仓库根**启动：`mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.workingDirectory=$(pwd -W)"`（workingDirectory 相对 backend 解析，必须传绝对路径，否则读不到根 `.env` 回落 root/root）。
- **管理端**：开发一律用 Vite 5173（`/api` 代理到 8080）；8080 上的管理端是 `backend/.../static` 构建产物，需 `npm run build:backend` 同步。
- **关键环境变量**：`REG_*`（平台四凭证 + 两个 URL）、`WX_APPID/WX_APPSECRET`、`WX_GATEWAY_TRUSTED_SHA256`（云出口自签网关证书 SHA-256 白名单，逗号分隔支持轮换）、`WX_GATEWAY_TRUST_SELF_SIGNED`（默认 false；云托管 Pod 每次发布会换出口自签证书，固定指纹不可持续，生产置 true 时仅对微信 `jscode2session` 的 RestTemplate 按 `CN=api.weixin.qq.com` + 自签放行，其余 HTTPS 仍严格 PKIX；开启后该链路不再做指纹固定，存在同链路自签证书截获 AppSecret 的风险，仅在云托管出口可信边界内使用）、`JWT_SECRET/JWT_EXPIRE_HOURS`、`COS_BUCKET/COS_REGION/COS_AUTH_URL`（托管桶走内网临时凭证；`COS_SECRET_ID/KEY` 仅自建桶）、`SEED_DEMO_DATA`（生产必须 false）、`APP_WORK_DURATION_MINUTES`（默认 30）、`APP_CHECKIN_THRESHOLD_METERS`（默认 200）、`REG_LEGACY_UPLOAD_ENABLED`（默认 false）、`APP_LEGACY_MODULES_ENABLED`（默认 false）、`SERVER_PORT`（容器 80）。
