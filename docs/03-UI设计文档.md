# 一、设计原则

1. **现场优先**：维保人员戴手套、强光、单手操作场景——大点击区（≥88rpx）、大字号、少键盘输入（能选不填）
2. **强引导**：核心流程（签到→作业→签名→签退→确认→上报）步骤条可视化，禁止的操作给出原因和出路（如定位超阈→如实提示重试，不伪造）
3. **状态透明**：离线、弱网、上报中/失败/成功全程可见，界面不显示未发生的"已同步"字样
4. **高对比**：户外强光可读，正文深灰 #1A1A1A 于白底，禁用浅灰大段文字
5. **极简收敛**：仅交付"基本维保作业 + 重庆监管要求"，不做装饰性设计与功能蔓延（docs/01 §10 范围裁剪清单为唯一权威口径）

> **【V1.1 修正】"大字号"原则的量化口径**
>
> V1.0 §1 提"大字号"、§5.1 又规定"文字次要（不小14px）"，但 §5.2 给出辅助文字 `26rpx`。**按微信 750rpx=375px 换算，26rpx = 13px < 14px，自相矛盾。** V1.1 已修正字号表（见 §7.2）。
>
> 换算基准（供设计执行）：`1px = 2rpx`，即 `14px = 28rpx`、`16px = 32rpx`、`18px = 36rpx`。

# 四、核心流程交互设计

## 4.1 现场作业主流程（9 步闭环，V2.0 重写）

```
工单台(今日任务) → 工单详情
  → ① 扫码签到（扫码确认→定位校验→水印自拍；双人经动态码验证）
  → ② 作业清单（A–D 逐项三态，关键项★/拍照/说明书判定/本次无需执行）
  → ③ 电子签名（主维保+配合人员）
  → ④ 签退自检（未完成项拦截）
  → ⑤ 生成维保记录（原始时间戳固化）
  → ⑥ 维保记录预览 ★新增（完整记录单，见 §6）
  → ⑦ 使用单位确认（安全管理员免登录签字，与预览同源）
  → ⑧ 2.6 上报平台（20 字段自动上报）
  → ⑨ 人工重传兜底（失败标"待人工"，不自动重试）
```

| 环节 | 交互要点 |
|---|---|
| ① 签到 | 扫码确认工单 → 定位校验（显示实时距离）→ 水印自拍（时间/定位/电梯/姓名）→ 提交；双人作业先经动态码验证；定位失败如实提示、严禁伪造坐标兜底 |
| ② 作业清单 | 检查项 A–D 逐项三态（正常✓/异常✗/不涉及—）；**关键项★**标红+异常必拍；"按说明书判定"填文字结论；周期性条目"本次无需执行"置灰并标注下次执行时间，**勾选后不进入本次维保记录** |
| ③ 电子签名 | 主维保+配合人员分别手写签名（横屏签名板） |
| ④ 签退自检 | 未完成项红色列出并拦截；显示作业时长、双人签名状态 |
| ⑤ 生成记录 | 签退成功即生成完整记录（原始时间戳固化，不可修改） |
| ⑥ 记录预览 | 完整记录单：电梯信息+类别码 / 签到签退含经纬度 / 检查项结果（仅实际执行项）/ 照片墙 / 维保双人签字 / 安全管理员签字（确认后回填）/ 上报状态 |
| ⑦ 使用单位确认 | 分享确认链接 → 安全管理员免登录查看记录 → 签字确认；结果本地归档不上报（TSG 第七条留痕） |
| ⑧ 上报平台 | 2.6 接口 20 字段自动上报，成功标"已上报" |
| ⑨ 兜底 | 失败标"上报失败(待人工)"，**不自动重试**，管理端逐条人工重传 |

## 4.2 子流程（3 条）

1. **双人作业**：主维保生成 60 秒动态码（每 5 秒刷新）→ 配合人员扫码验证同时到场 → 携码签到 → 双人签名。（已裁：3 次失败锁定+管理端解锁，仅保留基本校验，不匹配可重试）
2. **离线作业**：无网时签到/作业/签名本地保存（**保留原始时间戳**）→ 恢复网络自动补传（照片/签名断点续传）；离线缓存量与队列在小程序"我的→离线缓存管理"可见。
3. **急修单闭环**：登记（扫码回填电梯→S 码→描述→照片→停梯标记）→ 列表/详情 → 单位签字闭环。

## 4.3 异常与边界场景

| 场景 | 处理 |
|---|---|
| 扫码但无该电梯工单 | 提示"未找到工单"+电梯编号，引导联系管理员 |
| **电梯坐标未登记** | **灰色提示"该电梯位置未登记，本次仅记录定位"，不拦截**；上报管理端补录 |
| **定位超阈值** | 如实提示实际距离+可重试；**严禁伪造坐标兜底** |
| **定位失败** | 如实提示（8s 超时兜底），可重试；记录如实标注 |
| 定位权限被拒 | 引导 `wx.openSetting`，如实提示 |
| 动态码不匹配 | 明确提示原因，可重试（无锁定） |
| 检查项未完成 | 签退拦截，红色列出未完成项 |
| **关键项异常无照片** | 拦截"关键项异常必拍" |
| "按说明书判定"无说明书 | 提交后标"待复核"，进管理端抽检清单 |
| 周期性条目"本次无需执行" | 置灰+标注"下次执行：YYYY-MM"，可人工点选执行；**不进入本次维保记录** |
| 上报失败 | 工单详情显示"上报失败（待人工处理）"，管理员手动重传；**默认无自动重试**（幂等未确认） |
| 离线中断 | 本地队列+自动补传，状态条常驻（🟢在线/🟡弱网/🔴离线） |
| 使用单位确认超时 | 固定到期提醒（无复杂预警配置） |

# 八、检查项模板路由（品种 × 维保类别码）

> V2.0 新增维度：V1.6 及此前模板仅按**电梯品种（category）**路由；本次按用户要求增加**维保类别码（workType）**维度，作业项目集 = 品种 × 类别码。

## 8.1 品种维度（决定附件表）

| 品种 category | 模板表 |
|---|---|
| 曳引与强制驱动 | TSG 附件 A（A-1～A-4） |
| 自动扶梯与自动人行道 | 附件 B（B-1～B-4） |
| 液压电梯 | 附件 C（C-1～C-4） |
| 杂物电梯 | 附件 D（D-1～D-4） |

## 8.2 类别码维度（决定周期项目，叠加）

| 类别码 | 含义 | 周期项目集 |
|---|---|---|
| FM | 按需维保 | 按合同约定（默认参照年度完整项） |
| HM | 半月保 | 附件-1 表（如 A-1） |
| TM | 季度保 | -1 + -2 表 |
| SM | 半年保 | -1 + -2 + -3 表 |
| OY | 年度保 | -1～-4 全表 |

**示例**：曳引电梯 A 栋 1#，HM 半月保 → 显示附件 A-1 半月检查项目（约 15 项）；OY 年度保 → A-1+A-2+A-3+A-4（约 31 项）。工单创建时由后端按 品种×类别码 生成项目集，前端清单页按此渲染并显示类别码标签。

## 8.3 周期性条目（与类别码路由并存）

- 少数条目非每次执行（如限速器安全钳联动试验：曳引每 2 年、液压每 5 年校验）——不随类别码叠加进入本次项目集，按 **执行周期/季节约束/年限条件** 字段判定：
  - 满足周期 → 清单置灰显示"本次无需执行（下次执行：YYYY-MM）"，可人工点选执行
  - **标记"本次无需执行"的条目不进入本次维保记录与预览**（V2.0 用户决策）
- 消防/防爆电梯**禁止使用标准附件**，须走自定义模板（基于标准模板复制后增删改，`source=CUSTOM`）
