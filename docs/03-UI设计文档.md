## 1. 设计原则

1. **现场优先**：维保人员戴手套、强光、单手操作场景——大点击区（≥88rpx）、大字号、少键盘输入（能选不填）
2. **强引导**：核心流程（签到→作业→签退）步骤条可视化，禁止的操作给出原因和出路（如定位超阈→引导提交申诉）
3. **状态透明**：离线、弱网、上报中/失败/成功全程可见
4. **高对比**：户外强光可读，正文深灰 #1A1A1A 于白底，禁用浅灰大段文字

> **【V1.1 修正】"大字号"原则的量化口径**
>
> V1.0 §1 提"大字号"、§5.1 又规定"文字次要（不小14px）"，但 §5.2 给出辅助文字 `26rpx`。**按微信 750rpx=375px 换算，26rpx = 13px < 14px，自相矛盾。** V1.1 已修正字号表（见 §5.2）。
>
> 换算基准（供设计执行）：`1px = 2rpx`，即 `14px = 28rpx`、`16px = 32rpx`、`18px = 36rpx`。

## 4. 核心流程交互设计

### 4.1 现场作业主流程（V2.2：已取消人脸）

```
接单(订阅消息) → 扫码进入工单
  → 步骤① 签到确认（工单+人员信息核对）
  → 步骤② 定位校验（绿色✓距离xxx米 / 红色✗超阈值→申诉入口
                     / 灰色⚠坐标缺失→仅留痕不拦截）
  → 步骤③ 水印自拍存证（可跳过但标记待核查，管理端可见）
  → 检查项逐项执行（进度条 n/m，关键项强制拍照）
  → 双人签名（主维保→配合人员）
  → 签退自检（全部通过→定位校验→签退）
  → 工单"待确认" → 自动上报智慧平台 → 使用单位确认 → 归档
```

> **【V1.1】三处界面表述修正**
>
> ① **定位校验增加第三种态**：该电梯坐标未采集（`geo_status=UNKNOWN`）时显示灰色态「位置未登记，本次仅记录定位」，**不做拦截**——否则每台未登记坐标的电梯都会无法签到。详见 01 文档 §3.4.1。
>
> ② **"自动上报"改为"上报（失败待人工处理）"**：因 V1.5 未定义幂等性，默认关闭自动重试，失败会停在"待人工处理"，界面需如实展示。工单详情上报状态标签：`未上报 / 上报中 / 已上报 / 上报失败(待人工) / 上报失败(重试2/3)`。
>
> ③ **"使用单位确认"不显示任何"已同步平台"字样**（V1.5 无确认上报能力）。

### 4.1.1 双人到场验证交互（V1.1 新增）

V1.0 在 §4.3 提到"签到3次失败（双人动态码不匹配）"，但**没有任何界面设计**。V1.1 补齐：

| 角色 | 交互 |
|---|---|
| 主维保 | 签到页点「生成动态码」→ 全屏展示 **60秒倒计时**动态二维码（每5秒刷新，含防截屏水印），并**禁止截屏/录屏**（`wx.setClipboardData` 提示 + 截图检测告警） |
| 配合人员 | 扫一扫该动态码 → 校验有效期与工单匹配 → 校验"与主维保签到间隔 ≤30分钟" → 通过则完成配合人员签到 |
| 失败 | 动态码过期/不匹配/已使用 → 明确提示原因，**累计3次失败锁定工单**，管理端远程解锁（`approval` 走 `UNLOCK` 类型） |
| 降级 | 动态码不可用（手机故障、网络差）→ 允许"**主管授权代签到场**"，须主管在管理端确认，留痕并标记 |

> 后端接口须配套：`POST /workorders/{id}/dynamic-code`（生成/轮换）、`POST /workorders/{id}/checkin` 增 `dynamicCode` 字段、`POST /workorders/{id}/unlock`（解锁）。V1.0 的接口文档中**这三者均缺失**。

### 4.2 离线状态设计

- 顶部常驻状态条：`🟢在线` / `🟡弱网` / `🔴离线（已缓存 n 条，将自动补传）`
- 离线时：签到时间与GPS由本地记录；检查项正常填写；照片存本地文件系统
- 恢复网络：弹层提示"开始补传"，按时间顺序逐条上传，逐条打勾消失

### 4.3 异常与边界场景

| 场景 | 处理 |
|---|---|
| 扫码但无该电梯工单 | 提示"未找到工单"+电梯编号，引导联系管理员或创建临时任务 |
| **电梯坐标未登记** | **灰色提示"该电梯位置未登记，本次仅记录定位"**，**不拦截**；同时上报管理端补录 |
| 定位权限被拒 | 引导 `wx.openSetting`，同时提供"手动输入现场照片申诉"兜底 |
| 签到3次失败（双人动态码不匹配） | 工单锁定，管理端远程解锁（交互见 4.1.1） |
| **该维保人员 platform_id 未同步** | 排班时**直接禁止派工**并提示"人员尚未完成平台同步"；管理端"平台同步看板"给出失败原因 |
| **使用单位手机号互斥未通过** | 排班前拦截，提示**具体是哪两个角色冲突**及到哪修改，不给"请检查资料"这类无用提示 |
| **消防/防爆电梯未配置检查项模板** | 排班时拦截，提示"该品种须按制造单位要求配置维保项目"（TSG第二条） |
| **检查项为"按本机说明书判定"** | 展示为文字结论项而非数值输入；若该电梯未上传说明书，提交后自动打"待复核"并进管理端抽检清单 |
| **周期性条目"本次无需执行"** | 灰显并标注"下次执行：YYYY-MM"，允许人工点选"本次仍要执行" |
| 上报失败 | 工单详情显示"上报失败（待人工处理）"，管理员手动重传；**默认无自动重试**（幂等未确认） |

> **【V1.1】中性态色值补充**：V1.0 只有"正常/警告/危险"三级语义色，导致"坐标未登记""本次无需执行""待复核"这类**不阻断操作但需要用户知情**的状态被迫借用警告色（橙色）——现场人员会误以为出了问题。V1.1 补充中性灰 `#8C8C8C`，三态区分明确：绿=完成、灰=不适用/待补、橙=需要注意、红=异常/危险。

### 5.2 字号与间距

> **【V1.1 修正】V1.0 字号与自身"≥14px"规定冲突**
>
> V1.0 §5.1 规定"文字次要（不小14px）"，§5.2 却给出辅助文字 `26rpx` —— 按 `1px = 2rpx` 换算，**26rpx = 13px < 14px**，自相矛盾。V1.1 修正如下，并同时上调正文以落实 §1"大字号、强光可读"原则。

| 用途 | V1.0 | **V1.1 修正** | 折算px | 依据 |
|---|---|---|---|---|
| 页面标题 | 36rpx | 36rpx | 18px | 保持 |
| 卡片标题 | 32rpx | 32rpx | 16px | 保持 |
| **正文** | 30rpx | **32rpx** ↑ | **16px** | 原15px偏小，不满足"户外强光可读" |
| **辅助说明** | 26rpx ✗ | **28rpx** ↑ | **14px** | 满足 §5.1 自定的 ≥14px 下限 |
| 极小标注（仅角标） | — | 24rpx | 12px | **仅限图标角标/时间戳等装饰性信息，禁止承载需阅读的正文** |

### 6.3 困人救援登记页（V1.1 新增，最高优先界面）

> **TSG T5002 第五条(四)：直辖市抵达时间不超过 30 分钟。** 此界面服务于法定时限的现场留痕，设计以"最快录入 + 自动计时"为第一原则。

```
┌────────────────────────────────┐
│  困人救援登记        ● 计时中 02:41│  ← 红色计时（接通电话即开始）
├────────────────────────────────┤
│  电梯  渝A12345  龙湖花园3栋       │
│  被困人数  [ 3 ] 人               │
├────────────────────────────────┤
│  接警时刻   14:23:05   ●已记录     │  ← 页面打开即记录，不可事后改
│  出动时刻   [ 14:25:10 ]  [记录]  │  ─ 联动值班电话
│  抵达时刻   [        ]    [记录]  │
│  解救时刻   [        ]    [记录]  │
├────────────────────────────────┤
│  预计抵达剩余 27:19               │
│  ⚠ 超30分钟将自动标记并上报负责人    │
├────────────────────────────────┤
│  原因 [困人（轿厢停止运行）]        │
│  处置 [____]  照片 [+] [+]        │
├────────────────────────────────┤
│  [ 保存草稿 ]  [ 完成救援 ]        │
└────────────────────────────────┘
```

设计要点：
- **接警时刻在页面打开瞬间自动写入且不可编辑**（防止事后补录美化数据）
- 抵达时刻录入后，**抵达耗时自动计算并与 30 分钟比对**，超限立即红框提示并标记 `is_timeout`
- 出动/抵达/解救时刻均提供**一键"现在"**按钮，减少现场输入
- 走电话告警通道，**不依赖订阅消息**（推送可能不可达）
- 离线可用（井下无信号），恢复后补传
