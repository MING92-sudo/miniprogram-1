# 1. 测试策略总览

| 层次 | 范围 | 工具 | 覆盖率要求 |
|---|---|---|---|
| 单元测试 | 状态机、校验、计算、解析 | JUnit5 + Mockito | 核心模块 **≥80%**，上报适配层 **≥90%** |
| 集成测试 | 模块间（工单→记录→上报） | Spring Boot Test + Testcontainers(MySQL/Redis) | 关键链路 100% |
| 契约测试 | 平台 8 接口 | WireMock（Mock 8 个接口 + 异常场景） | 全场景 |
| 联调验证 | 真实平台测试环境 | 真实凭证 | 见第 4 章（**含阻塞项**） |
| 端到端 | 小程序全流程 | 真机 iOS/Android 各一台 | P0 流程全覆盖 |
| 验收测试 | 交付验收 | 依 01 文档功能清单 | 逐条签字 |

**分层理由**：上报适配层的每一个分支都对应监管数据，故其覆盖率要求高于常规业务代码——"2.6 失败了怎么办"比"2.6 成功时返回什么"更需要测试。

# 2. 单元测试重点清单

## 2.1 上报状态机（02 §5.2）

| 用例 | 输入 | 期望 |
|---|---|---|
| 正常上报 | SUBMITTED → 平台200 | REPORTED，`report_time` 写入 |
| 保守分支失败 | `reg.retry.auto=false` + 平台500 | 立即 `FAILED_MAX`，**不写重试队列** |
| 乐观分支重试 | `reg.retry.auto=true` + 连续失败 | RETRY_WAIT 3 次（30s/2m/10m）→ FAILED_MAX |
| 乐观分支幂等 | 已有 success=1 记录 | 直接返回成功，**不发 HTTP** |
| 人工重传 | FAILED_MAX + manual-retry | 重置 REPORTING |
| 确认终态 | REPORTED → 确认 | CONFIRMED，**无任何 HTTP 调用** |
| Token失效 | 平台返回认证失败 | 清缓存重登 + 重试**1次**，仍失败→FAILED_MAX |

> ⚠️ **"确认终态无 HTTP 调用"必须有测试断言**，防止有人日后"顺手"加一次上报。

|---|---|---|

- 周期性条目：A-4-6（≤15年每2年/>15年每年）、B-4-4（每2年）、C-4-6（每5年）三者规则**互不相同**，须分别测试
- 季节性条目：D-2-5 雨季前、D-3-12 冬季前，跨年边界须测试
- `judge_type=MANUFACTURER` + 该电梯未上传说明书 → 提交后 `need_review=true` 进抽检清单

## 2.5 签到与定位（02 §5.4）

- Haversine 距离：0m / 199m / 200m(边界) / 201m
- 阈值回退链：电梯级 → 品种级 → 全局，逐级验证
- `geo_status=UNKNOWN` → **不拦截**（code 不为 1001），记录留痕
- `geo_status=PROVIDED` + 超阈 → `1001` + 申诉入口
- 动态码：过期(>60s) / 工单不匹配 / 已使用 / 与主签到间隔>30min
- 动态码连续失败 3 次 → `1003` 锁定

## 2.6 离线与时间口径（02 §5.3）

- 离线跨日补传：`start_time`/`end_time` = **本地采集时间**，`report_time` = 服务端时间，**两者不相等且各自正确**
- 批量提交 500 项上限、超限拒绝
- 批量部分失败：已成功项不回滚，失败项可单独重传
- 补传顺序按 `originalRecordId`（或 recordedAt）稳定排序

## 2.7 平台响应解析（04 B.5）

| 场景 | 响应形态 | 期望 |
|---|---|---|
| 标准 | `{code:"200", data:[...]}` | 取 `data` |
| 根级数组 | `{code:"200", message:.., [...]}` | 取根级 |
| data 内列表 | `{code:"200", data:{list:[...]}}` | 取 `list` |
| **无法解析** | 全部落空 | **抛 REG_PARSE_ERROR + 告警**，**严禁返回空列表** |

> 最后一条是**防灾难性测试**：一旦误判空列表，全员 `platform_id` 丢失 → 全系统不可派工。

## 2.8 困人救援计时（03 §6.3）

- 抵达耗时 = 抵达时刻 − 接警时刻
- 29:59 不超时；**30:01 超时**（边界）
- `call_time` 创建后**不可修改**（接口层断言拒绝二次写入）
- 离线状态下的时间记录与恢复后补传

## 2.9 冻结与不可变（TSG 第十条）

- 维保记录提交后，任何 update 接口调用均应失败
- `maintain_record_snapshot` 写入后不受档案变更影响
- 使用单位换安全管理员后，历史记录的 `elevatorAdminister` 仍为原值
- 确认签名撤销走审批，原确认记录保留

# 9. 缺陷分级

| 级别 | 定义 | 处理时限 |
|---|---|---|
| **Blocker** | 上报链路失败 / 数据丢失 / 数据被篡改 / 法定时限未满足 | 立即修复，阻断发布 |
| **Critical** | P0 功能不可用（如签到、签退、签名任一失败） | 24小时内 |
| **Major** | P1 功能异常但有绕行 | 3个工作日 |
| **Minor** | 体验问题、文案、样式 | 迭代修复 |

> **Blocker 判定补充**：任何可能导致**监管平台出现错误或虚假数据**的缺陷，一律 Blocker——包括但不限于幂等判断错误、手机号互斥漏检、快照被档案变更污染。
