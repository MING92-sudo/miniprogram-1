# 一、项目审查

## 1.1 核心结论

**文档与代码存在明显落差：`docs/` 描述的是"目标蓝图"（Spring Boot 单体 + MySQL/Redis/COS + Vue3 管理端），代码是"可演示原型 + 空壳后端"。**

三句话概括现状：

1. **小程序前端最完整**——`app.json` 注册 **23 个页面**，UI/交互/业务逻辑齐全、能跑通，但**全部跑在 mock 上**（`config/index.js` 的 `useMock: true`）。
2. **后端基本是空壳**——`backend/` 是 Spring Boot 3.3.4（Java 17 / Maven）骨架，只有 `/health` 可用；登录/上报控制器返回 501，token 与转发服务直接抛 `UnsupportedOperationException`；**且前端根本没有调用它**。
3. **真正能用的平台集成只有一段脚本**——`scripts/probe-reg-api.ps1`，它已经摸清了平台的关键"坑"（登录用 GET、业务接口用表单、根路径 `/api/wlw/maintenance/`）。

## 1.2 已就绪的资产（可复用）

| 资产 | 位置 | 状态 |
|---|---|---|
| 小程序 UI + 业务 mock 闭环 | `pages/` 23 页、`services/` 9 个、`mock/`、`utils/` | ✅ 完整可跑，分层干净 |
| 需求/架构/接口/联调文档 | `docs/01~07` | ✅ 质量极高，已逐字核对 TSG 与 V1.5 |
| 平台联调结论 | `docs/07` + `scripts/probe-reg-api.ps1` | ✅ 登录已通、只读接口已通 |
| 后端骨架 + 配置模板 | `backend/`、`config/`、`.env.example` | ⚠️ 空壳，但配置项齐全 |

## 1.3 关键缺口（按严重度）

### A. 后端与真实链路（最严重）

- 后端仅 `/health` 可用；`AuthController`/`ReportController` 返回 501；`PlatformTokenService.getToken()`、`PlatformClient.forward()` 抛异常。
- 前端没接后端：关掉 `useMock` 后，`config/index.js` 的 `apiBaseUrl` 指向**监管平台直连**，且发 JSON 而非平台要求的表单、路径也不匹配 → 必坏。
- 无数据库、无 COS 上传、无微信登录（code2session）、无 JWT。

### B. 平台对接（外部阻塞 + 内部待做）

- 已打通：2.1 登录（GET）、2.2 主体查询、2.7 电梯查询。
- 待闭环：2.3（需真实使用单位 entityID）、2.4（需真实人员+证书 PDF）、2.5（被 2.3 阻塞）、2.6/2.8（需真实电梯+双人）。
- **最高风险：`originalRecordId` 幂等性未确认**（docs/06 问题 7）——直接决定重试策略，关系是否会在监管平台产生重复/虚假记录。

### C. 前端未完成点（小、需收口）

- 双人作业只做一半：`pages/order/dynamic-code.js` 验证结果没接回签到流程；`checkin.js` 硬编码 `role:'PRINCIPAL'`。
- `pages/unit/pending.wxml` 用了不存在的字段 `completedAt`；救援无详情页（`services/rescue.js` 的 `getRescueDetail` 是死代码）。
- 空组件 `components/navigation-bar/`（0 文件）；TDesign 依赖已装但未引用。
- 演示残留：`home` 页"模拟扫码"按钮、`checkin` 的 `FALLBACK_LOCATION`（合规场景会伪造定位）、`login` 的 demo 账号。
- 离线补传的照片 fileIds 丢失（`item-form.js` 的 `saveOffline`）。

### D. 配置/安全

- `.env` 有真实凭证，但 Java **不会读它**（无 dotenv），`mvn spring-boot:run` 起来凭证为空。
- `config/index.js` 硬编码腾讯 LBS key；`.env` 的 `REG_API_BASE_URL` 少了 `/maintenance`（与 `.env.example` 不一致）。
- `.env` 注释自述"凭证曾在聊天中暴露" → 建议轮换。

## 1.4 风险与待决事项

| 风险 | 说明 | 处置 |
|---|---|---|
| 幂等性未确认 | `originalRecordId` 若平台不幂等，自动重试会产生重复/虚假记录 | 保守分支：默认关闭自动重试；联调实测幂等后再开启 |
| 合规法定项未实现 | 自行检查、应急演练、困人救援 30min、第八条技术参数 | P1 前端闭环 + P4 归档落库 |
| 外部阻塞 | 2.3~2.8 缺真实测试数据、2.3 自建关系 500 待平台答复 | 并行跟进，不阻塞 P1 |
| 凭证已暴露 | `.env` 注释自述曾在聊天暴露 | 建议向平台申请轮换 |

# 二、开发计划

## 2.1 总体思路

**先做完整可用的本地业务，再用最小代理后端接通平台，最后打通上报闭环。**

理由：上报是硬需求、是最大外部风险点、且已具备联调基础；但本地业务 UI 已 90% 完成，收口成本低、不依赖平台接口，可先行交付完整产品形态。后端保持"薄代理"，避免过早投入 13 模块 + Vue3 管理端的大单体。

## 2.2 决策基线

| 决策项 | 结论 |
|---|---|
| 后端形态 | **最小代理先行**：token 中控 + 平台接口转发 + 核心上报；13 模块与管理端后置 |
| 近期优先级 | **本地业务完整优先**：P1 纯前端收口，平台上报后置到 P3 |
| 重试策略 | 保守（默认不自动重试），待幂等性书面确认后开启 |

## 2.3 阶段划分

### P0 · 定基线（本轮已完成，剩外部依赖）

- ✅ 后端形态：最小代理；✅ 优先级：本地业务完整优先。
- 并行跟进（不阻塞 P1）：平台幂等性答复、真实联调数据（测试电梯编码 / 2 名维保人员 / 使用单位 entityID）、`dev`/`test` 环境划分。

### P1 · 本地业务收口（前端为主，1~2 周）★ 优先

把 C 类缺口全部补齐，让 23 页在 mock 下形成完整闭环：

- **双人作业**：`dynamic-code.js` 验证结果接回签到流程，`checkin.js` 支持 `PRINCIPAL/ASSISTANT` 切换。
- **救援**：新增详情页并接通 `getRescueDetail`（或删死代码）。
- **修复字段**：`unit/pending` 的 `completedAt` → 实际字段。
- **去演示残留**：删 `home` 页模拟扫码按钮、`login` demo 账号；`checkin` 的 `FALLBACK_LOCATION` 改为"定位失败则如实提示"，不再伪造坐标（合规关键）。
- **离线补传真实化**：照片补传、队列幂等。
- **空组件**：补齐 `navigation-bar/`（4 文件）或删除。
- **合规项闭环**：自行检查、应急演练、困人救援（30min）、使用单位确认/评价——UI + 本地流程走通，数据暂存本地。
- **检查项模板**：257 行种子数据先以 mock/静态数据落地，保证作业流程完整可走。

**验收**：mock 下全业务（含双人、离线、合规项）端到端可用，无任何演示残留。

### P2 · 最小代理后端 + 接通（1~2 周）

后端保持"薄代理"，不做 13 模块：

- token 中控（GET 登录 + 缓存 TTL=expires_in−60s + 401 清缓存重登重试 1 次）。
- 2.2/2.7 只读转发（表单编码，`String.valueOf(code).equals("200")` 兼容数字/字符串）。
- RestTemplate 超时（连接 3s / 读 30s，文件接口 120s）+ 认证路径 URL 脱敏日志。
- 引入 `.env` 加载；最小 `schema.sql`（电梯/工单/记录/上报日志等核心表）。
- 前端：环境切换 + `apiBaseUrl` 指向后端 + `useMock` 可关；微信登录 code2session→openid→JWT。

**验收**：小程序登录走真后端，本地业务数据落 DB，2.2/2.7 从平台拉回真实数据。

### P3 · 平台上报闭环（2~3 周）

- 2.6 上报：签退冻结快照（`maintain_record_snapshot`）+ 表单组装 + `reg_upload_log` 脱敏落库 + 保守重试（默认不自动重试）。
- 2.3/2.4/2.5 + 人员 `platform_id` 同步（2.4→2.5 轮询→按证书号精确匹配）。
- 幂等性验证（联调必做）：专用测试电梯连交 3 次相同 `originalRecordId`，核对平台记录数。

**验收**：真实测试电梯签到→签退→上报平台成功且无重复。

### P4 · 文件与合规归档（2 周）

- COS 直传（STS 临时凭证）+ 水印照片/签名归档。
- 检查项模板正式落库（257 行种子 + 消防/防爆自定义模板）。

### P5 · 部署与收尾（按需，管理端延后）

- Nginx + Spring Boot + MySQL（+ Redis 按需）+ COS；备份/归档满足 ≥4 年留存（TSG 第十条）。
- Vue3 管理端整体后置，必要时先出最小统计报表。
