# 一、项目审查

## 1.1 核心结论

**文档与代码存在落差：`docs/` 描述的是"目标蓝图"（Spring Boot 单体 + MySQL/Redis/COS + Vue3 管理端），代码当前是"mock 全闭环前端 + 空壳后端 + 已打通的平台脚本链路"。**

三句话概括现状：

1. **小程序前端最完整**——`app.json` 注册 **27 个页面**（新增救援详情、故障列表、电梯档案两页、合规台账三页、unit/sign、login），UI/交互/业务逻辑齐全、能跑通，但**全部跑在 mock 上**（`config/index.js` 的 `useMock: true`）。
2. **后端基本是空壳**——`backend/` 是 Spring Boot 3.3.4（Java 17 / Maven）骨架，只有 `/health` 可用；登录/上报控制器返回 501，token 与转发服务直接抛 `UnsupportedOperationException`；**且前端根本没有调用它**。
3. **平台链路已由脚本全链路打通**——`scripts/probe-reg-api.ps1`、`test-23-27.ps1`、`test-25-worklist.ps1`、`test-full.ps1` 已于 2026-09-30 完成 2.1—2.8 真实环境全链路验证（登录 GET、业务表单、multipart 文件、20 字段上报全过），唯一遗留：`originalRecordId` 幂等性待平台管理端核对。

## 1.3 关键缺口（按严重度）

### A. 后端与真实链路（最严重）

- 后端仅 `/health`、`/api/count` 可用；`AuthController`/`ReportController` 返回 501；`PlatformTokenService.getToken()`、`PlatformClient.forward()` 抛异常。
- 前端没接后端：关掉 `useMock` 后，`config/index.js` 的 `apiBaseUrl` 指向**监管平台直连**，且发 JSON 而非平台要求的表单、路径也不匹配 → 必坏。
- 无数据库、无 COS 上传、无微信登录（code2session）、无 JWT。

### B. 平台对接（外部阻塞 + 内部待做）

# 二、开发计划

## 2.1 总体思路

**先做完整可用的本地业务，再用最小代理后端接通平台，最后打通上报闭环。**

理由：上报是硬需求、是最大外部风险点、且已具备联调基础；但本地业务 UI 已 90% 完成，收口成本低、不依赖平台接口，可先行交付完整产品形态。后端保持"薄代理"，避免过早投入 13 模块 + Vue3 管理端的大单体。

## 2.2 决策基线

| 决策项 | 结论 |
|---|---|
| 后端形态 | **最小代理先行**：token 中控 + 平台接口转发 + 核心上报；13 模块与管理端后置 |
| 近期优先级 | **本地业务完整优先**：P1 纯前端收口，平台上报后置到 P3 |
| 重试策略 | 保守（默认不自动重试），待幂等性书面确认后开启 |

## 2.3 阶段划分

### P0 · 定基线（已完成）

- ✅ 后端形态：最小代理；✅ 优先级：本地业务完整优先。
- ✅（V1.1）真实联调数据已备齐并全链路实测通过；幂等性与管理端核对、`dev`/`test` 环境划分转入 P3 跟踪。

### P1 · 本地业务收口（前端为主，1~2 周）★ 大部分已完成（V1.1）

原缺口大部分已收口（见 1.3.C 已完成清单），剩余项：

- **离线补传真实化**：照片/签名 fileIds 补传、队列幂等（mock 层已收口，真实后端联调时回归）。
- **检查项模板**：257 行种子数据先以 mock/静态数据落地（当前模板引擎按品种/频次生成，行数未逐条核对 TSG 原文）。
- **演示残留清理**（接真实后端前）：`login` demo 账号、`home` 演示入口。
- ~~**TDesign 依赖决策**~~：已移除 `tdesign-miniprogram`；后续如启用再按 AGENTS 重新评估并同步文档。

**验收**：mock 下全业务（含双人、离线、合规项）端到端可用 ✅（已达成）；收口上述剩余项后关闭本阶段。

### P2 · 最小代理后端 + 接通（1~2 周）

后端保持"薄代理"，不做 13 模块：

- token 中控（GET 登录 + 缓存 TTL=expires_in−60s + 401 清缓存重登重试 1 次）。
- 2.2/2.7 只读转发（表单编码，`String.valueOf(code).equals("200")` 兼容数字/字符串）。
- RestTemplate 超时（连接 3s / 读 30s，文件接口 120s）+ 认证路径 URL 脱敏日志。
- 引入 `.env` 加载；最小 `schema.sql`（电梯/工单/记录/上报日志等核心表）。
- 前端：环境切换 + `apiBaseUrl` 指向后端 + `useMock` 可关；微信登录 code2session→openid→JWT。

**验收**：小程序登录走真后端，本地业务数据落 DB，2.2/2.7 从平台拉回真实数据。

### P3 · 平台上报闭环（2~3 周）★ 前置验证已提前完成（V1.1）

原 P3 的最大外部阻塞（2.3—2.6 缺真实数据/接口未上线）已于 2026-09-30 通过 `scripts/test-full.ps1` 等脚本**在真实环境提前打通**（含 2.6 上报 20 字段全过、幂等重放），P3 剩余为把脚本验证过的调用方式沉淀进后端代码：

- 2.6 上报：签退冻结快照（`maintain_record_snapshot`）+ 表单组装 + `reg_upload_log` 脱敏落库 + 保守重试（默认不自动重试）。
- 2.3/2.4/2.5 + 人员 `platform_id` 同步（2.4→2.5 轮询→按证书号精确匹配）。
- 幂等性最终确认：重复提交已实测返回成功，**待平台管理端核对记录数**（我方测试数据：212520 电梯，originalRecordId=1948179075784507801 上报 1 次 + 重放 1 次）。

**验收**：真实测试电梯签到→签退→上报平台成功且无重复。

### P4 · 文件与合规归档（2 周）

- COS 直传（STS 临时凭证）+ 水印照片/签名归档。
- 检查项模板正式落库（257 行种子 + 消防/防爆自定义模板）。

### P5 · 部署与收尾（按需，管理端延后）

- Nginx + Spring Boot + MySQL（+ Redis 按需）+ COS；备份/归档满足 ≥4 年留存（TSG 第十条）。
- Vue3 管理端整体后置，必要时先出最小统计报表。
