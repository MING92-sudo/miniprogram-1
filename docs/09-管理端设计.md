# 一、目标与范围

## 1.1 定位

管理端服务 docs/01 定义的三个管理角色（班组长/维保部管理员/系统管理员），覆盖**调度监控、异常闭环、档案维护、数据统计**四大场景。后端 P2/P3 已就绪的能力（41 条业务路由、2.6 上报与手动重报、`reg_upload_log`、2.2—2.8 平台链路）直接复用，管理端不重复造轮子。

## 1.2 分期范围（MVP 优先）

**第一期（本设计范围）**：

1. **工单监控看板**：今日到期/即将到期/超期/进行中统计，工单列表筛选与详情（只读复用小程序契约）。
2. **上报异常闭环**：`reportStatus=FAILED` 记录清单 + 手动重报（复用 `POST /platform/records/{id}/reupload`）；上报日志查询（`reg_upload_log`，脱敏展示）；**维保记录导出 PDF**（含照片/签字/签到签退时间，✅ 后端已实现）。
3. **平台同步看板**：docs/04 A.3 `GET /reg/sync-status` 口径（待同步人员/位置待补电梯/最近同步时间）+ 手动触发 `POST /platform/sync`。
4. **档案管理**：维保单位、使用单位、人员、电梯四类档案的查看与维护（含手机号互斥预校验 1002、电梯平台信息回填入口）。
5. **合规台账**：自行检查/应急演练/救援/故障记录查看（复用现有 `/inspects`、`/drills`、`/rescues`、`/faults` 路由）。
6. **基础统计报表**：工单完成率、隐患分布（S0—S7）、按人员/电梯维保量；Excel 导出。

**第二期（后置，不在本期）**：排班调度与延期审批（A.5）、检查项模板管理（A.4.2）、预警规则配置、订阅消息管理、用户权限管理、日志审计、定位异常申述审核。

## 1.3 不做清单（防蔓延）

- 不做检验机构检测功能（docs/08 既有决策）。
- 不在管理端提供平台凭证配置界面——`REG_*` 只能走云托管环境变量（AGENTS §2.1）。
- 不提供批量自动重试入口——2.6 失败不自动重试（代码硬编码，无开关），重报只能逐条人工触发。

# 二、技术选型与工程结构

| 项 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue ≥3.4 + Vite | docs/02 §3 蓝图选型 |
| UI | Element Plus | docs/02 蓝图；仅用于管理端，不违反小程序端"不引入新 UI 框架"规则（AGENTS §3） |
| 图表/导出 | ECharts + exceljs | docs/02 §3 |
| 状态/路由 | Pinia + Vue Router | JWT 存内存 + localStorage，401 统一跳登录 |
| HTTP | axios | 统一信封 `{code, message, data}` 解包；写接口自动携带 `X-Idempotency-Key` |

```
admin/
├─ index.html / vite.config.js      # dev 代理 /api → http://localhost:8080
├─ src/
│  ├─ main.js / App.vue
│  ├─ router/                       # 路由 + 角色守卫
│  ├─ stores/auth.js                # token / userInfo / role
│  ├─ api/                          # 按域拆分（order.js、archive.js、report.js…）
│  ├─ views/                        # 页面（见 §四）
│  └─ components/
└─ .env.example                     # 仅 VITE_API_BASE，无凭证
```

**跨域策略**：开发期 Vite 代理规避 CORS；生产走同域反代（§五），后端不开放跨域。

## 3.1 角色矩阵

## 3.2 认证

- 复用 `POST /auth/login`（账号=手机号 + 密码，JWT 72h）。登录响应含 `role`，前端据此渲染菜单与路由守卫。
- 后端登录接口增加管理端角色白名单：仅 `LEADER/ADMIN/SYS_ADMIN` 可签发管理端会话（小程序端角色不受影响）。
- 路由守卫：未登录 → `/login`；角色越权 → 403 页。

# 五、部署

- **生产**：微信云托管「静态托管」承载管理端 SPA（或 Nginx :443 托管静态资源并反代 `:8080` 后端，docs/02 两种形态均可）；SPA 与 API **同域**，避免 CORS 与跨域 Cookie 问题。
- **开发**：`npm run dev` + Vite proxy → `http://localhost:8080`。
- 环境变量：仅 `VITE_API_BASE`（默认同域反代路径）；**任何平台凭证不得进入管理端代码或其环境配置**（AGENTS §2.1）。
- `SEED_DEMO_DATA` 生产置 false；演示种子新增 `ADMIN` 角色账号（账号/初始密码写入 README，首登强制改密二期补）。

# 六、关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 手动重报直接复用 P3 端点 `/platform/records/{id}/reupload`（记录 ID）；docs/04 A.3 的 `/records/{originalRecordId}/manual-retry` 目标契约收敛为同一实现 | 避免两套重报入口；幂等红线一致 |
| 2 | 上报日志 `request_digest` 管理端只读展示脱敏版，本期不做"明文权限" | AGENTS §2.4；明文需求出现时再加独立权限 |
| 3 | 手机号互斥校验（1002）放**服务端**，管理端仅展示 `conflicts[]` 角色对 | docs/04 B.7：校验前移至建档期 |
| 4 | 电梯"位置待补"（坐标缺失）在看板与档案页高亮 | docs/01 §3.4.1 降级策略，提示补录坐标 |
| 5 | 管理端不做平台凭证/重试开关配置界面 | AGENTS §2.1/§2.3 安全红线 |
| 6 | 统计聚合在后端完成（`/admin/stats`），前端只渲染 | 避免记录 JSON 全量拉到浏览器 |

# 七、测试与验收
