# 云托管部署手册（微信云托管）

> 目标形态：微信云托管承载「后端服务（容器）」+「管理端 SPA（静态托管）」+「云 MySQL」，三者在同一自定义域名下按路径路由实现同域（`/api/* → 后端`，`/* → 静态托管`）。
> 小程序端代码另走微信开发者工具上传（与后端无关）。
> 创建：2026-10-01。部署凭证（REG_*、WX_APPSECRET、JWT_SECRET、DB 密码）只允许进云托管控制台环境变量，严禁写入仓库（AGENTS §2）。

## 1. 部署拓扑

```
小程序(微信端) ──► https://<自定义域名>/api/* ──► 云托管「后端服务」(Spring Boot :80)
管理端SPA ──────► https://<自定义域名>/* ────────► 云托管「静态托管」(admin/dist)
                            ▲
                      云 MySQL(内网，Flyway 自动建表)
```

## 2. 前置条件（人工，本手册无法代做）

| # | 事项 | 说明 |
|---|---|---|
| 1 | 微信小程序主体 + **云开发/云托管**环境已开通 | 需「服务号/小程序管理员」微信扫码登录 |
| 2 | 云托管「数据库」实例（或腾讯云 MySQL CDB）已建 | 拿到内网 `host:port` 与账号密码 |
| 3 | 平台接口凭证 `REG_USERNAME/KEY/APPCODE/SECRET` | 见 `.env`（本地已有），生产是否已分配/开通白名单见 docs/06 |

## 3. 部署步骤

### 步骤 A：数据库（Flyway 自动建表，无需手工 SQL）

1. 云托管控制台创建「MySQL」实例，库名 `maintenance`，字符集 `utf8mb4`。
2. 记录内网地址（云托管容器内可直连）供步骤 B 环境变量使用。
3. 表结构由后端启动时 Flyway 自动执行 `V1–V6` 迁移 + 演示种子（`SEED_DEMO_DATA=true` 首启后改 `false`）。
   > V6 为 P0 串号修复：清掉历史 `dev_openid` 与重复 openid（受影响账号置空、下次登录重新绑定），并给 `sys_employee.openid` 加唯一约束。
   > 部署后核对：`SELECT openid, COUNT(*) FROM sys_employee WHERE openid IS NOT NULL GROUP BY openid;` 每行计数应为 1；若历史 `DEV_OPENID` 曾改成自定义值（非默认 `dev_openid`）且只落在少数账号上，需人工确认残留并置空。

> ⚠️ **删库后必须重建**（2026-10-01 云托管首部署踩坑）：后端 JDBC URL 已带 `createDatabaseIfNotExist=true`，目标库不存在时由驱动自动建库（账号需对该库有 CREATE 权限）；但**若手动删库排障**，务必重建同名空库，否则 Hikari 连接失败、容器启动失败（liveness probe 报 `connection refused`）。重建：`CREATE DATABASE IF NOT EXISTS maintenance CHARACTER SET utf8mb4;`（**勿**指定 `utf8mb4_0900_ai_ci`，该排序规则仅 MySQL 8 支持，5.7 会报错）。
>
> ⚠️ **云端 MySQL 版本**：云开发 MySQL 为托管 5.7（不可自助升级）；迁移脚本已全部兼容 5.7（V2 的 JSON 列已改 `LONGTEXT`）。

### 步骤 B：后端服务（容器）

1. 云托管控制台「服务管理 → 新建服务」：
   - 部署方式：**代码仓库 / 本地代码**（仓库根 `Dockerfile` 即“云托管流水线构建入口”，自动构建 `backend/` 源码）。
   - 或「本地镜像」：本机 `docker build -f backend/Dockerfile -t maintenance-backend .` 后推送到云托管镜像仓库。
2. 服务设置（`backend/container.config.json` 提供初始值）：端口 `80`，最小实例 `0`，规格 1C2G，扩缩容 cpu 50%。
3. **环境变量**（控制台「服务设置 → 环境变量」逐个填，禁止写进任何文件）：

   | 变量 | 值 |
   |---|---|
   | `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD` | 云 MySQL 内网地址与账号 |
   | `JWT_SECRET` | ≥32 字节强随机串 |
   | `WX_APPID` / `WX_APPSECRET` | 微信小程序凭证（**生产必填**）——`/auth/bind-wechat`、`/auth/wx-login` 用 code 换真实 openid；不配置这两个接口直接报错（openid 无 `DEV_OPENID` / `X-WX-OPENID` 兜底，P0 修复已移除）。AppSecret 手工粘贴，勿经聊天/文档 |
   | `SEED_DEMO_DATA` | 首启 `true`，建表后改 `false` |
   | `APP_WORK_DURATION_MINUTES` | `30`（待业务确认） |
   | `REG_AUTH_LOGIN_URL` / `REG_API_BASE_URL` | 见 `.env.example` |
   | `REG_USERNAME` / `REG_KEY` / `REG_APPCODE` / `REG_SECRET` | 平台凭证（本地 `.env` 中有，**手工粘贴，勿经聊天/文档**） |
   | `REG_LEGACY_UPLOAD_ENABLED` | `false` |
   | `COS_BUCKET` / `COS_REGION` / `COS_AUTH_URL` | 托管桶（`COS_AUTH_URL` 默认值即可） |
4. 部署后 `GET https://<域名>/health` 应返回 `UP`。
5. **确认 V6 已执行**（V6 是唯一修复存量串号数据的一步）：
   - `SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank;` → 应有 `6 ... success=1`；
   - `SELECT openid, COUNT(*) FROM sys_employee WHERE openid IS NOT NULL GROUP BY openid;` → 每行计数必须为 1。
   - 若云端 Flyway 未执行 V6（Flyway 10 Community 对 MySQL 5.7 的支持需实测；被拒绝时任何迁移都不会跑），
     用 mysql 客户端手工执行 `backend/src/main/resources/db/migration/V6__p0_openid_unique.sql`
     （脚本按表设计为可重复执行：清 `dev_openid`、清重复 openid、幂等增删索引），
     之后 `flyway repair` 或重建服务使 `flyway_schema_history` 与实际库一致。

### 步骤 C：管理端 SPA（静态托管）

1. 本机构建：`cd admin && npm run build`（产物 `admin/dist/`；Windows 下用工作区内临时目录作 TMP/TEMP，见 admin/README）。
2. 云托管「静态托管」上传 `admin/dist/`。
3. 生产 API 基址已内置 `VITE_API_BASE` 默认 `/api`（同域），无需额外改。

### 步骤 D：同域路径路由

云托管「自定义域名」下配置**路径路由**：
- `/api/*` → 后端服务（**无需** strip 前缀：后端 `ApiPrefixFilter` 已统一把 `/api/**` 改写为 `/**`，小程序直连根路径与管理端带 `/api` 前缀可同域共存）；
- `/*` → 静态托管（SPA）。

### 步骤 E：小程序端切生产

1. `config/index.js`：`ENV='prod'`、`prod` 填 `https://<自定义域名>`、`useMock=false`。
2. 微信开发者工具「上传」→ 小程序后台「提交审核/发布」。
3. 确认后端 `WX_APPID` 与本小程序 AppID 一致（不一致时 jscode2session 报 40013/40029，绑定/一键登录会失败）。
