# 电梯无纸化维保系统——维保记录表单与急修记录表单设计

**文档编号**：DM-ELEV-FORM-2026-001
**文档版本**：V1.0
**编制日期**：2026 年 11 月 12 日
**编制依据**：《TSG T5002—2017 电梯维护保养规则》原文（第五条、第七条、第八条、第十条、附件 A—D）
**关联文档**：《01-需求文档.md》§3.8/§3.9、《04-接口文档.md》A.0.3、《09-管理端设计.md》§6.12、《12-未完成事项清单.md》

> 本文定义两张对外出示/归档的表单：**《电梯维护保养记录》**与**《电梯急修记录单》**。表单既是小程序记录预览的内容口径，也是 `GET /admin/records/{id}/export-pdf`、`GET /admin/faults/{id}/export-pdf` 的版面口径——预览与 PDF 必须逐格一致。

## 0. 为什么按这个格式

| 依据条款 | 对表单的硬性要求 | 本设计的落点 |
|---|---|---|
| 第七条 (一) | 记录至少包括电梯基本情况和技术参数（整机制造、安装、改造、重大修理单位名称，电梯品种(型式)，产品编号，设备代码，型号，基本技术参数） | §3.2 「一、使用单位与设备基本情况」12 格 + 品种参数行 |
| 第七条 (二) | 使用单位、使用地点、使用单位内编号 | §3.2 首行 4 格 |
| 第七条 (三) | 维保单位、维保日期、维保人员（签字） | §3.3 「二、维保作业信息」+ §3.7 签字区 |
| 第七条 (四) | 维保的项目(内容)、进行的维保工作、达到的要求、发生调整、更换易损件等工作时的详细记载 | §3.4 项目表四列 + §3.5 「四、发现问题及处理」 |
| 第七条 末段 | 维保记录应当经使用单位安全管理人员签字确认 | §3.7 第三签字位 |
| 第八条 | 按品种给出必备技术参数（曳引/液压/杂物/扶梯人行道 四套） | §3.6 品种 × 参数矩阵 |
| 第十条 | 无纸化记录格式/内容/要求须合规，数据保存过程中不得更改，可实时查询 | 快照冻结导出、表单带记录编号+打印时间、页脚声明 4 年留存 |
| 第五条 (五) | 对电梯发生的故障等情况，及时进行详细的记录 | §4 急修记录单 |
| 第五条 (四) | 困人故障：直辖市或设区市 ≤30 分钟到场，其他地区一般 ≤1 小时 | §4.3 响应时限标注 |
| 附件 A—D | 项目(内容)与基本要求逐字来自表 A-1～D-4，且按"除符合上表外还应当符合下表"累加 | §3.6 表号与累加式标题；项目行逐字取模板 |

## 1. 版式总则（两张表单共用）

| 项 | 规定 | 说明 |
|---|---|---|
| 纸张 | A4 纵向（210×297mm） | 归档打印通用 |
| 页边距 | 左右 18mm、上下 15mm | 给左侧装订留白 |
| 字体 | STSong-Light（CID，不嵌入字体文件） | 后端 `BaseFont.createFont("STSong-Light","UniGB-UCS2-H", NOT_EMBEDDED)` |
| 字号 | 标题 16pt 粗 / 区块标题 9.5pt 粗 / 表头 9pt 粗 / 正文 8.5pt / 注脚 7.5pt | 年度维保 76 行仍需可读 |
| 颜色 | 单色（黑 + 浅灰 #F2F2F2 标签格） | 黑白打印即标准表格样式，不依赖彩色 |
| 表格线 | 0.5pt 细线，外框同宽 | 与纸质台账观感一致 |
| 空值 | 统一 `—`；档案未采集的技术参数写 `—（档案未采集）` | 不用空白格，避免被误读为漏填 |
| 分页 | 项目表**表头每页重复**；页脚 `第 x 页 / 共 y 页` | 附件 A—D 年度项 76 行必然跨页 |
| 页脚 | 留存声明 + 打印时间 + 页码 | 第十条"不得更改"的取证线索 |

- 维保类别 → 项目范围：半月=`表X-1`；季度=`表X-1＋表X-2`；半年=`＋表X-3`；年度=`＋表X-4`（累加式）。
- 副标题写作：`附件A 表A-1～表A-2（半月、季度）`；单表只写一个表号。
- 类别为"按需维保（FM）"时副标题写 `按需维保（依合同约定项目，参照表X-1）`。

### 3.7 区块「五、现场安全防护确认」「六、现场照片留证」「七、签字确认」

- 安全防护：`safety_json` 的 warning/barrier/powerOff/twoPerson 逐项渲染勾选符，未采集时全部打 `□`。
- 勾选符固定用 `■`（已确认）/ `□`（未确认）与结果列 `√` / `×` / `—`：STSong-Light（UniGB-UCS2-H）不含 `☑`/`☐`（U+2611/U+2610），用它们会出现空白格——这是导出后肉眼核对的结论，不可改回。
- 照片：检查项 `photoFileIds` 优先，回退 `photos` 与 `photos_json`；两列网格，无照片打印"无现场照片"。
- 签字三位 + 盖章位：`workerSignatureUrl`、`assistantSignatureUrl`、`signatureUrl`（使用单位安全管理人员）。签字图缺失时打印 `＿＿＿＿＿＿＿＿` 待手签，加载失败打印"（签字图片加载失败）"，不得静默留白。
- 签署日期：维保人员两位取签退日期；使用单位位留手写线 `签署日期：＿＿＿＿年＿＿月＿＿日`（系统未单独记录确认时间，见 §6 G3）。

| 二 | 到场时间 / 响应时长 | `arrivedAt`（该梯当日首次签到）/ `arrivedAt − createdAt` 分钟数 |
| 三 | 故障现象 | `desc` |
| 三 | 现场检查情况 | `siteDesc` |
| 三 | 故障原因分析 | 未采集 → `—（现场检查情况见上；系统未单独采集）`（§6 G2） |
| 三 | 处理措施（含更换零部件） | `result`（闭环时写入） |
| 三 | 恢复运行时间 / 待办 | `finishedAt` / `todoDesc` |
| 四 | 现场照片 | `photos[]`，按 URL 拉取，失败降级 `（照片加载失败）` |
| 五 | 使用单位签字 + 日期 | `signature` / `confirmedAt` |

### 4.3 响应时限标注（第五条(四)）

- 表单只呈现**事实与法定期限选项**，不自动判"合规/违规"：同时列出"≤30 分钟（直辖市或设区的市）"与"≤60 分钟（其他地区）"两个勾选框，并打印实际响应时长。
- 到场时间以该梯当日首次签到为准（`DirectoryService.firstCheckinToday`），无签到不留痕、不编造。
- 地区类型（直辖市/设区市/其他）系统不采集，故不做自动判定——这是刻意的合规保守设计，避免导出件出现错误的"合格"结论。

## 7. 验收清单（打印口径）

1. 年度维保（76 项）导出：项目表跨页时**表头重复**，页脚页码连续且"共 y 页"正确。
