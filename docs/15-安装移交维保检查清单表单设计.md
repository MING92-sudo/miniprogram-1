# 电梯无纸化维保系统——安装移交维保检查清单与整改清单表单设计

**文档编号**：DM-ELEV-FORM-2026-002
**文档版本**：V1.0
**编制日期**：2026 年 11 月 12 日
**编制依据**：《GB/T 10060—2023 电梯安装验收规范》原文（第 4 章安装验收前提条件、第 5 章 5.1—5.12 验收检查项目及要求、第 6 章 6.1—6.18 验收试验项目与试验要求、第 7 章验收规则、表 1「电梯安装验收项目分类」74 项）；《TSG T5002—2017 电梯维护保养规则》第五条第(六)项（档案留存）
**关联文档**：`docs/01`（需求）、`docs/04`（接口）、`docs/12`（待办）、`docs/13`（维保/急修表单）、`docs/14`（账号权限）、`docs/superpowers/specs/2026-11-12-handover-filing-unit-portal-design.md`（W1 移交状态机）

> 本文定义安装部 → 维保部移交环节的**三张表单**：
> 1. **《电梯安装移交维保检查清单》**——74 项标准检查表（移交单进入「现场查验中」时由系统自动生成整表，现场逐项填结果）；
> 2. **《电梯安装移交不合格项整改清单》**——检查清单提交后，只要存在「不合格」项，系统按**检查项序号 1:1 一一映射**自动生成整张整改清单，不允许手工增删行；
> 3. **《安装移交归档目录（一梯一档）》**——确认归档时生成，把上述两张单、20 项资料、逐项照片统一挂到该电梯档案下。
>
> 三张表单必须与系统数据**逐格一致**：小程序查验页、管理端详情、导出 PDF、一梯一档四处的字段与顺序同源。

## 0. 合规边界（先读）

| 序 | 边界 | 说明 |
|---|---|---|
| B1 | 本清单是**内部移交把关**，不是法定验收 | 法定安装验收结论以**监督检验报告**为准（清单 §二 D20 为强制项，缺件不得查验）。本清单判定只决定「是否允许从安装部移交到维保部」，**不得**在任何界面或导出件上表述为「验收合格」。 |
| B2 | 适用范围照抄标准第 1 章，不得扩大 | GB/T 10060—2023 只适用于**额定速度 ≤6.0 m/s 的曳引式电梯**与**≤0.63 m/s 的强制式电梯**；明确**不适用**液压驱动电梯、杂物电梯、家用电梯、仅载货电梯、斜行电梯。不适用品种**不自动生成**本清单（见 §3.2）。 |
| B3 | 消防员电梯 / 防爆电梯的附加项目不内置条款 | 5.11/5.12 只要求「增加 GB/T 26465 / GB/T 31094 中对应验收项目」。我方未采集这两份标准原文，**不得**凭印象编造子项：清单仅留「附页逐项记录」位，并强制填写所依条款号（宁缺不编，`docs/05 §7`）。 |
| B4 | 引用条款一律回填标准原文条号 | 本文每项检查要求都标注 GB/T 10060—2023 条号；后端模板的 `clause_no` 字段与导出 PDF 的条款列必须与该条号一致，不得只写「符合规范」。 |
| B5 | 判定规则照 7.2/7.3 原文 | 重要项目（表 1 备注列标「☆」）任一不合格即不合格；一般项目不合格 ≤8 项允许整改修复后复检；现场受限无法修复时，重要项目全合格 + 一般项目 ≤3 项，经协商准予验收但须制定有效控制措施。数值不得自行放宽。 |

### 3.2 适用范围与自动触发

| 触发输入 | 处理 | 说明 |
|---|---|---|
| `elevator.category` = 曳引与强制驱动电梯，且 `driveMode` 为曳引驱动（额定速度 ≤6.0 m/s） | 生成 74 项整表 | 标准第 1 章适用范围 |
| `category` = 曳引与强制驱动电梯，`driveMode` 为强制驱动（额定速度 ≤0.63 m/s） | 生成 74 项整表，序号 40 由 NA 变为必检 | 5.5.3 强制驱动卷绕 |
| 额定速度 >6.0 m/s（曳引式） | 生成整表 + 顶部红字提示「超出标准适用范围，参照执行，不适用部分由制造单位与买方协商确定」 | 标准第 1 章第二段原文口径 |
| `category` = 液压驱动电梯 / 杂物电梯 / 自动扶梯与自动人行道 | **不生成**本清单；移交单查验页显示「GB/T 10060—2023 不适用本品种」，要求上传该品种的**监督检验报告**与制造单位自检报告作为查验依据 | 宁缺不编（B2），禁止套用曳引式 74 项 |
| 特殊类别含消防员电梯 | 序号 55 必检，须在附页逐项记录 GB/T 26465 对应项目与条款号 | B3 |
| 特殊类别含防爆电梯 | 序号 56 必检，须在附页逐项记录 GB/T 31094 对应项目与条款号 | B3 |

**自动生成时机**：移交单 `status` 由 `DOC_SUBMITTING` → `INSPECTING`（3 必传资料齐全）时，后端一次性写入 74 条 `handover_check_item` 草稿（`result` 为空、`important` 取自模板、`item_no` 1—74）。**不随查验人变动重建**，避免已填结果丢失。

### 3.5 区块「三、检查项目及检查要求」

**列定义**（导出与页面同源）：

| 列 | 宽比 | 内容 | 来源 |
|---|---|---|---|
| 序号 | 5% | 1—74，固定不变（与表 1 一一对应，不按实际执行重排） | 模板 `item_no` |
| 项类 | 8% | G01—G13（见附录 A 分组） | 模板 `item_group` |
| 条款 | 9% | 5.1.1 / 6.18 等标准原文条号 | 模板 `clause_no` |
| 检查项目 | 20% | 表 1 项目名逐字 | 模板 `item_name` |
| 检查要求（要点） | 30% | 附录 A「检查要求」列，条款要点压缩 | 模板 `requirement` |
| 重要 | 5% | `☆` / `—` | 模板 `important` |
| 结果 | 6% | `√` / `×` / `—` | `result`：PASS/FAIL/NA |
| 实测值 | 8% | 数值+单位；试验项目必填 | `measured_value` |
| 照片 | 5% | 已挂照片张数（点开看缩略图） | `photo_file_ids` 计数 |

**规则**：

1. 74 项**不允许空结果**。提交时任一为空 → 422「第 N 项未填结果」；未适用必须选原因码（见 §3.5.1），不允许用 NA 代替未检。
2. `×` 项必须在 `fail_desc` 写现象；`☆` 项与试验项目（57—74）的 `×` 还必须附 ≥1 张照片，否则不得提交。
3. `☆` 项置 `—`（不适用）属**高危操作**：须选择原因码 + 备注，并触发**维保部经理审批**（`handover_sign` 节点 `SITE_INSPECT`）；未审批前整单不可提交 —— 防止用 NA 掩盖重要项不合格。
4. 试验项目（57—74）除结果外必须填 `measured_value`，且导出件打印数值；无实测值只有结论的一律视为无效记录（第十条「数据不得更改」的取证要求，`docs/13 §1`）。

#### 3.5.1 不适用（NA）原因码

| 码 | 含义 | 举例 |
|---|---|---|
| NA-01 | 本梯无此配置/部件 | 无机房、无滑轮间、无轿厢安全窗、无补偿装置 |
| NA-02 | 品种/型式不涉及 | 非强制驱动电梯的序号 40；非曳引式电梯的序号 70 |

### 3.6 区块「四、判定结论」——按 7.2 / 7.3 自动计算

设：`F_imp` = 重要项目（☆）不合格数，`F_gen` = 一般项目不合格数，`N` = 不适用项数，`P` = 合格数，`P + F_imp + F_gen + N = 74`。

| # | 判定条件 | 结论码 | 结论文案（表单打印） | 状态机去向 |
|---|---|---|---|---|
| 1 | `F_imp = 0` 且 `F_gen = 0` | `QUALIFIED` | 合格，准予移交 | → `PENDING_CONFIRM` |
| 2 | `F_imp = 0` 且 `1 ≤ F_gen ≤ 8` | `RECTIFY` | 一般项目不合格 N 项，须整改修复后复检（7.2） | → `RECTIFYING`，生成整改清单 |
| 3 | `F_imp ≥ 1` | `DISQUALIFIED` | 重要项目 N 项不合格，判定不合格；应全面修复后重新申请验收（7.2、7.3） | → `RECTIFYING`，整改清单逐条标「强制整改」 |
| 4 | `F_gen > 8` | `DISQUALIFIED` | 一般项目不合格 N 项（>8），判定不合格；应全面修复后重新申请验收（7.2） | → `RECTIFYING` |
| 5 | `F_imp = 0` 且 `1 ≤ F_gen ≤ 3` 且 现场受限无法修复 且 三方协商确认 且 已制定控制措施 | `CONDITIONAL` | 有条件移交：重要项目全部合格，一般项目不合格 N 项（≤3），经安装单位、维保单位、使用单位协商确认并制定控制措施（7.3） | → `PENDING_CONFIRM` + `handover_issue=TRUE` |

**实现口径**：

- 第 5 条是第 2 条的**例外通道**，必须同时满足 5 个条件，缺一即按第 2 条走整改；系统逐条校验并回显缺失条件，不允许「勾一下就过」。
- 三方协商确认复用 `handover_confirmation` 的字段口径（`key_tool_check` / `leftover_issue` / `counterpart_sign_name` / `counterpart_sign_file_id`）；该表现按 `filing_id` 关联外接建档（W2），W1 移交须在 V32 增设 `handover_id` 或建同构表，不得混用 `filing_id`。
- 控制措施文本写入：①表单「控制措施」栏；②首保工单 `todo_desc` 前缀 `[移交遗留]`；③通知安装部（沿用 V28 `handover_issue` 回写链路）。
- 结论码由后端计算并随检查快照冻结（`conclusion` 列），**任何角色不得手工改写**；确需更正只能作废重填（新版本号），保留原记录。

### 4.3 自动生成与映射规则（核心）

| # | 规则 | 说明 |
|---|---|---|
| M1 | **一对一**：一个 `×` 检查项 = 一条整改记录 | 禁止合并同类项、禁止一条整改覆盖多个检查项（否则无法证明"是哪一项不合格"） |
| M2 | **触发即全量**：提交检查清单时若 `count(result='FAIL') ≥ 1`，在同一事务内一次性生成**整张**整改清单 | 不做「挑几条生成」，也不允许先交清单后补整改项 |
| M3 | **双向可追溯**：整改记录 `item_no` 外键指向 `handover_check_item.item_no`；导出件与详情页均显示「检查序号 42 ↔ 整改序号 R42」 | 用户原话「哪一项不合格就自动映射到整改清单」的落点 |
| M4 | **不可增删**：页面无「新增整改项」按钮；后端 reject 任何 `item_no` 不在本次 `FAIL` 集合内的写入 | 防止手工造项绕过检查 |
| M5 | **强制整改标记**：`F_imp ≥ 1` 时该条与整单标「强制整改」，`recheck` 不通过则整单永不可回 `PENDING_CONFIRM` | 7.2/7.3 |
| M6 | **逐条复验**：现有 `recheckRectify` 一次性把所有未复验项置同一结果，须改为按 `rect_id` 逐条复验；**全部 PASS** 才回 `PENDING_CONFIRM` | 与 M1 配套，否则一条通过=全部通过 |
| M7 | **重开清单**：整改后复验发现新问题，由查验人新增「复验发现」条目（`source=RECHECK`），仍 1:1 关联检查项，不改原 R 项结论 | 保留痕迹，不覆盖历史 |
| M8 | **作废与重建**：整单作废（`INSPECTING` 阶段重填）时旧整改清单置 `voided`，新清单一律重新生成，不复用编号 | 第十条「不得更改」的取证要求 |

### 4.4 与状态机的对接

```
INSPECTING ──提交查验──┬─ 全部合格 ────────────────────────→ PENDING_CONFIRM
                       ├─ 一般项 ≤8 / 重要项 ≥1 / 一般项 >8 ─→ RECTIFYING（生成整改清单）
                       └─ 有条件移交（≤3 + 现场受限 + 三方）→ PENDING_CONFIRM（handover_issue=TRUE）

RECTIFYING ──整改上传──→ 逐条复验 ──全部 PASS──→ PENDING_CONFIRM
```

## 10. 验收清单（打印与链路口径）

1. 74 项整表生成：进入 `INSPECTING` 即存在 1—74 全部行，序号/项类/条款/项目/要求与附录 A 逐字一致，`☆` 共 49 项。
2. 缺项拦截：任一结果为空提交 → 422 且提示项号；`×` 无描述、`×` 无照片（☆/试验项）均 422。
3. 判定矩阵 5 条路径各跑 1 例：`QUALIFIED` / `RECTIFY`（一般项 1—8）/ `DISQUALIFIED`（重要项 ≥1）/ `DISQUALIFIED`（一般项 >8）/ `CONDITIONAL`（≤3 + 5 条件齐备）。
4. 整改清单自动生成：2 个 `×` → 恰好 2 行 `R42`/`R68`，页面无「新增」入口，直接 POST 非 FAIL 项 → 拒绝。
5. 逐条复验：1 项 PASS、1 项 FAIL → 状态仍 `RECTIFYING`；全部 PASS → `PENDING_CONFIRM`。
6. ☆项置 NA：未审批不可提交；审批后表单打印 `—` + 原因码 + 审批人。
7. 导出 PDF：74 行跨 4—6 页，每页重复表头，页脚「第 x 页/共 y 页」自计，页脚含「不替代监督检验」声明；照片缺失打印「（照片缺失：第 N 项）」。
8. 归档：一梯一档出现 7 类文件；SHA-256 校验一致；重复归档幂等（不重复建电梯/首保工单）。
9. 越权：非本节点角色签字 `1403`；安装部角色看不到其他项目移交单（班组/部门数据域）。
10. 不适用品种（液压/杂物/自动扶梯）：不生成 74 项表，页面显示不适用说明与「上传承运检验报告」入口。
