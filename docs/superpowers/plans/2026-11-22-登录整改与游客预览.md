# 登录页整改 + 游客预览 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复两条提审驳回（登录无取消/返回出口、协议链接点击无响应），新增未登录可浏览的静态预览页，微信一键登录对未绑定用户可见并走"账号密码登录后自动绑定"。

**Architecture:** 纯小程序端改动 + mock 契约对齐。后端 `/auth/wx-login`（未绑定返回 422）与 `/auth/bind-wechat` 已上线，零改动。预览页纯静态（无接口、无真实数据）。

**Tech Stack:** 微信小程序原生（CommonJS / WXML / WXSS），mock `mockRequest`，Node 断言脚本（scripts/verify-*.js 模式）。

**Spec:** `docs/superpowers/specs/2026-11-22-登录整改与游客预览-design.md`

## Global Constraints

- 小程序端 CommonJS、ES2018、2 空格缩进、单引号；文案只从 `constants/index.js` 取，禁止页面硬编码。
- 接口改动两处同步：`services/` + `mock/server.js`；方法签名不随 mock↔真实切换变化。
- 注释遵循 AGENTS §5.4：少写，只留安全约束/业务不变量，一行最多两句。
- 提交信息一行中文、动词开头；AI 协作用 `codex/` 前缀分支，完成后按主题收敛回 master。
- 提交前根 `npm run lint` 必须通过；改动 mock 后跑对应 verify 脚本。
- 设计文档与计划文档属临时产物，不入提交（`docs/superpowers/` 不 add）。

## Review Focus

- 未登录用户在登录页按返回（无栈）：期望去预览页，不死循环（Task 2，靠 `back()` 登录态分支保证；页面栈行为无法脱离真机自动化，列 AGENTS §6 人工走查清单）。
- 微信 code 是一次性且 5 分钟有效：登录页暂存 code 后若用户停留超期/换号重试，bind 失败必须静默兜底并提示去「我的」绑定，不能阻断登录（Task 4 步骤实现）。
- 预览页绝不可以发任何带 `needAuth` 的请求：页面不引用 `services/*`，常量数据全部来自 `constants`（Task 3 约束，靠代码评审保证）。
- 已登录用户冷启动仍会 reLaunch 进工作台、看不到预览页：`pages/login/index` 的 `onReady` 既有逻辑不动（Task 4 不触碰）。
- 客户多单位账号（`needSelectUnit`）走选单位页：自动绑定微信必须发生在 `enterApp` 分流之后、且不干扰选单位流程（Task 4 步骤实现——bind 只在直接 `enterApp` 成功路径触发，needSelectUnit 分支不触发）。

- [ ] **Step 1: 写失败校验**

1. `req('POST', '/auth/wx-login', { code: 'UNBOUND' })` → 抛错且 `e.code === 422`

- [ ] **Step 1: 改 `utils/nav.js`**

顶部 require 补 `isLoggedIn`；`back()` 改为：

```js
function back() {
  const pages = getCurrentPages()
  if (pages.length > 1) { wx.navigateBack(); return }

  reLaunch('/pages/preview/index')
}
```

注释一行（现有注释基础上改）：无栈时未登录回预览页，避免弹回登录页死循环。
