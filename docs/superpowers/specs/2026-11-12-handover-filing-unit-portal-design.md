**日期**：2026-11-12
**状态**：草案（已过 builder 审查，待进入实施计划）
**范围**：第一阶段（合规底线）三条工作线 W1 移交 / W2 外接建档 / W3 使用单位门户 + 横切改造（维保日历、区域、角色）
**依据**：需求文档 V1.1 + 对话澄清结论（已全部确认）

## 1. 意图与核心原则

现有系统是一套成熟的「无纸化维保」模块（电梯台账、工单、签到、清单、签退、双签、派单、急修、平台上报 2.3/2.4/2.6）。本次新增两个「电梯档案创建来源」和一个「使用单位登录门户」，并补「维保日历」「区域划分」两项横切能力。

**核心原则**：以**电梯主数据**为共享底座，以**移交归档事件**或**外接建档归档事件**作为维保模块的自动启动信号，实现从建档到历次维保的全生命周期数据贯通。

**关键基数口径（已确认）**：一张移交单 / 一张外接建档单 = **一台电梯（1:1）**。一个项目多台电梯 = 多张单（项目级资料按电梯重复上传，可接受）。

## 2. 目标 / 非目标 / 反目标

### 目标
- W1 移交、W2 外接建档两条状态机各自跑通，归档时自动建电梯 + 触发首保工单。
- W3 使用单位门户：登录查看本单位电梯 / 维保记录 / 急修记录 / 待签字确认 + 报修（复用急修链路）。
- 维保人员可查看「未来 12 个月维保日历」（半月/季度/半年/年度）。
- 电梯按区域归类，维保人员只看到本区域电梯。
- 电梯法定字段在归档时写定一次，维保模块只读继承。

### 非目标（本期不做，留阶段二/三）
- 备件库存联动、资质有效期预警、延期审批、使用单位评价看板、故障趋势分析。
- 移交/外接建档本身不上报监管平台（只有维保记录走 2.6）。

### 反目标（做了反而失败）
- 不在维保模块开放法定字段手改（避免绕过归档校验）。
- 不把「首保」做成新的维保类别（统一按半月保 FM 上报）。
- 不让使用单位 / 维保人员越权看到他人电梯（数据权限 fail-closed）。
- 不预先落库 12 个月维保计划（避免预生成计划与实际派单脱节）。

## 3. 约束

- 技术栈：小程序 CommonJS / Spring Boot 3.3.4 + MyBatis-Plus；Flyway 只追加新版本。
- 安全红线（AGENTS §2）：凭证不入库、日志脱敏、文件带时效签名（`FileStorageService.urlOf`）。
- 接口三处同步：`services/` + `mock/server.js` + `docs/04`。
- 派单只由定时任务驱动，读接口不触发副作用（AGENTS §3.6）。
- 工单号只经 `OrderNoIssuer`；写操作带 `X-Idempotency-Key`。
- 归档动作幂等（见 §4）。

## 4. 核心机制：归档事件驱动

「归档」是一个**事务性、幂等**的动作，在一个事务里执行：

1. 写电梯主表：`archive_source`（1=移交 / 2=外接 / 0=存量直建）+ 法定字段一次写定。
2. 写维保责任起始时间：移交 = 监督检验合格日；外接 = 接收日（交接确认签字时间）。
3. 绑定维保责任人 = 接收/接管工程师（复用电梯现有 `workerName/workerPhone/workerPlatformId`）。
4. 关联归档资料 / 随机文件到电梯（`AppFile`）。
5. **立即预建首保工单**（半月保 HM）：复用 `dispatchNow` 逻辑，`planTime` = 归档日 +15 日（移交）/ +3 日（外接，自然日）；工单写 `source_handover_id` 或 `source_filing_id` 回指来源单。定时派单任务看到已有 PENDING 单自然跳过，不破坏现有派单幂等。
6. 通知相关方。

**幂等**：归档写操作带 `X-Idempotency-Key`；状态已「已归档」则拒绝重复归档（终态防重，不重复建工单）。

**移交遗留问题闭环**：首保工单设「移交遗留问题」勾选项（`handover_issue` 标记）；首保签退时若勾选，回写来源移交单并通知安装部，形成跨模块异常闭环（需求 §2.2.5）。

## 6. 状态机与转移矩阵

### 6.1 移交（W1）—— 6 态（含整改分支）
```
待发起 → 资料移交中 → 现场查验中 → 待确认 → 已归档
                        ↓ 不合格
                     整改中 →（复验通过）→ 待确认
```
- **资料移交中**：必传卡点——监督检验报告 / 维保说明书 / 整机质量证明，缺一不可提交。
- **现场查验中**：维保部经理分配接收人员；安全装置/制动器不合格 → 强制整改。
- **待确认**：维保部经理确认**一步到位 = 归档**（不设独立中间审批）。
- **整改中**：安装部上传整改前后照片 → 原查验工程师复验 → 通过回「待确认」；超 3 工作日通知双方负责人。

### 6.2 外接（W2）—— 5 态
```
待建档 → 资料收集中 → 接管查验中 → 待确认 → 已归档
```
- **前置**：必须关联已生效合同（起始日 ≤ 建档日）；同一使用单位同梯已有生效合同 → 冲突提示。
- **接管查验中**：不合格项**不阻塞建档**，但责任归属必填写入交接确认单。
- **待确认**：交接确认单双方签字（我方账号 + 对方手写）→ 归档。

## 7. 签字模型（对话澄清结论）

| 场景 | 签字方式 | 存储 |
|---|---|---|
| 内部账号（维保部经理/安装部项目经理/维保人员） | **节点「通过」即签字**，账号名自动填写 | `handover_sign` 节点确认记录 |
| 外部人员（使用单位安全管理员/对方单位移交人） | 手写签名 | 复用现有「本机代签 / 分享链接」签名图 |
| 维保记录三签（主 + 配合 + 安全管理员） | 已存在，不改 | 现有 `work_order` 签字字段 + `/unit/records` token 签字 |

## 8. 区域划分与数据权限（已确认）

- `region` 区域主数据表；`elevator.region_id`、`employee.region_id` 两个可空外键。
- **区域 = 可见范围**：维保人员看到**本区域全部电梯**；「维保责任人」绑定（`workerPlatformId`）**只决定派单派给谁，不限制可见性**；组长额外可见本班组。
- 存量电梯/人员 `region_id` 为空 = 未分区（维持现状可见性，不因加字段导致历史数据突然看不见）。
- 前端：电梯台账（小程序 + 管理端）展示区域；管理端维护区域主数据 + 电梯/人员区域分配。

## 9. 首保派单与维保日历

### 9.1 首保基线
- 首保 = 半月保 **HM**（不新增类别，FM 是按需维保，勿混用）。
- **归档时立即预建**（§4 第 5 步），`planTime` = 归档日 +15 日 / 接收日 +3 日（**自然日**）。
- 派单目标 = 电梯维保责任人；`OrderNoIssuer` 发号；读接口不触发。

### 9.2 维保日历（新增，只读投影）
- **前向投影算法（新逻辑，非复用 DispatchService）**：从首保（首次半月保）日起，逐日推进 12 个月；每天按累加式规则 HM(15)→TM(90)→SM(180)→OY(365) 判定当天应做的最高类型，生成每台电梯未来 12 个月排期。
- **只读投影，不预先落库**；实际派单仍走现有「到期前一日」定时任务（`DispatchService`），避免预生成计划与实际派单脱节。
- 前端：维保人员「维保日历」页，看到自己名下/本区域电梯未来排期。

| 角色 | 现有 | 本期 |
|---|---|---|
| 维保部（LEADER/ADMIN/WORKER） | 有 | 加移交/外接建档入口 + 维保日历 + 区域过滤 |
| 安装部（INSTALLER，新增，单角色） | 无 | 只看「发起移交 + 已归档项目」，维保 tab 全隐藏；项目经理/资料员的差异由节点动作控制，不拆角色 |
| 使用单位（USE_UNIT，新增） | 无登录 | 一个单位一个账号，登录门户只看本单位电梯（`useUnitId` 谓词），只读 |

- 前端按角色渲染 tabBar（微信原生 tabBar 不可运行时切换，用自定义 tabBar 或首页按角色路由分发）。
- 后端强校验（越权 `1403`），前端隐藏只是体验。

## 13. 已确认决策（对话澄清，全部敲定）

1. 一张移交单 / 外接建档单 = **一台电梯（1:1）**。
2. 首保时限按**自然日**（移交 15 日 / 外接 3 日）。
3. 移交「待确认」经理确认**一步到位 = 归档**。
4. 使用单位报修从**本单位电梯列表选取**故障电梯。
5. 区域 = **结构化主数据表**；**区域 = 可见范围**（责任人绑定只决定派单）。
6. 使用单位 = **一个单位一个账号**（绑定 `use_unit`，`useUnitId` 即数据权限锚点）。
7. 首保上报类别 = 半月保 HM（`constants` 中 FM=按需、HM=半月，首保取 HM）；维保记录三签（主+配合+安全管理员）已存在不改。
8. 内部签字 = 账号节点确认；外部签字 = 手写（本机代签/分享链接）。
9. 首保**归档时立即预建**（planTime = 归档日 +15/+3 日）。

## 14. 默认值（已采纳，未获反对）

1. 使用单位门户：设计本轮一起出，开发排期放阶段一后半段。
2. 移交保留「整改→复验」分支；整改超 3 工作日通知双方负责人。
3. 合同：阶段一只做最小可用版（合同号/起止日期/电梯清单/生效状态）。
4. 存量电梯 `archive_source` 默认 `0 = 存量直建`；存量电梯/人员 `region_id` 默认空 = 未分区。
5. 维保日历为只读投影，不预先落库 12 个月计划。
6. 外接「资料缺失待补办」：生成补办任务，默认限期 30 天、超期提醒；豁免由维保部经理在「待确认」时一并审核。
7. 安装部不拆「项目经理 / 资料员」两角色，合并为单一「安装部」角色。
