## 1. 意图与核心原则

现有管理端（Vue3 + Element Plus，21 视图，12 角色码 / 24 能力码）与新设计蓝图（9 角色 / 71 权限码 / 6 数据范围 / 17 视图 / 深色工业风）是**两套不同的产品模型**。本次重构以新蓝图为目标，同时保留现有系统的监管合规核心（平台上报 2.1—2.8、上报异常人工重报、外接建档、区域主数据、检查项模板）。

**已确认的五项战略决策**（2026-11-14 对话）：

1. **蓝图对齐 + 合规保留**：视图层按新 IA 重组，权限模型向新码迁移，合规模块作为新增视图保留进新 IA。
2. **三端整体迁移**：后端角色目录/权限矩阵/数据范围迁移，管理端重组，小程序角色视图同步对齐；旧码设兼容期。
3. **保留扩展角色**：商务 `MAINT_BIZ`、质量 `MAINT_QUALITY`、安装员 `INSTALL_WORKER` 不在新 9 角色内，作为扩展角色保留并补权限码。
4. **Vue3 自建组件库**：放弃 Element Plus，按原型自建组件（顺带关闭 docs/12 D-05 包体问题）；AGENTS §4.3 同步修订。
5. **推进策略 A：底座先行、视图分批**：M0 设计 → M1 后端权限底座 → M2 组件库+壳 → M3/M4/M5 视图分批迁移，旧管理端全程可用，最后切换。

**核心原则**：

- 权限 = 功能码 + 数据范围 + 字段脱敏，三者服务端同时校验；前端隐藏只是体验（新设计 roles §8.2、docs/14 §12.2 同口径）。
- 合规红线（AGENTS §2/§3）在任何新功能下不得绕过：无自动重试、签字归属、签退快照上报、文件时效签名、读写谓词分离。
- Flyway 只追加；旧表旧列不删不改；322 单测不回退。

### 4.2 多角色规则

- 一人可多角色，权限取并集，数据范围逐角色判定；登录不选角色，后端下发 roles/perms/scope。
- **同部门内可兼任**（如 MAINT_SUP 兼 MAINT_TECH、CLIENT_ADMIN 兼 CLIENT_SIGNER）；**跨部门兼任仍禁止**（docs/14 R7，偏离 D-A2）。
- 多角色默认进入最高优先级工作台（维保 > 安装 > 使用单位），管理端/小程序内切换工作台重新拉取菜单。
- 角色/范围变更递增 `scopeVersion`，旧 token 失效；停用/离职沿用 R8（enabled=false + 会话清除）。

### 4.3 权限码

- 新设计 71 码全量采纳，`<domain>:<action>`，三态 `Y`（可操作）/ `C`（只读或需审批）/ `-`（禁止）；逐码归属以 roles §12 覆盖表为准。
- 扩展角色补码（M0 码映射表定义）：质量 `template:toggle`（检查项模板启停）+ 抽检动作码；商务合同/客户写码；安装员查验/整改码。
- 24 旧码 → 71+ 新码映射表为过渡期**唯一事实源**；未知角色/未知码一律拒绝（fail-closed，沿用 PermissionMatrix 初始化校验）。
- `C` 态的"需审批"语义由审批流承载（敏感导出、台账导出申请等），不是前端置灰了事。
- 按钮两档门控（roles §8.4）：永久缺权 = 原生 disabled + title 权限码；临时前置未满足 = aria-disabled + 可聚焦 + 捕获阶段拦截。后端校验仍是唯一安全边界。

### 4.4 数据范围（6 枚举，不新增）

| 范围 | 谓词 | 典型角色 |
|---|---|---|
| `SELF` | 本人创建/被指派 | MAINT_TECH（本人派工）、INSTALL_WORKER |
| `TEAM` | 本班组 | MAINT_TECH（班组共享池） |
| `PROJECT` | 项目部/被指派项目集 | MAINT_SUP（本项目部）、INST_PM/INST_CLERK（被指派安装项目） |
| `ORG` | 本组织及下级（组织树） | INST_MGR（安装部）、MAINT_QUALITY/MAINT_BIZ（维保部，商务限合同客户域） |
| `ORG_FLAT` | 仅本单位 | CLIENT_ADMIN / CLIENT_SIGNER |
| `ALL` | 平台全量（运维只读）/ 全部维保项目（department=MAINT 过滤） | PLATFORM_ADMIN / MAINT_MGR（双语义靠过滤条件区分，roles §5.1 决策 14） |

- **读写分离红线保留**：范围扩大只进读谓词；写谓词严格本人/本组/被指派（防代签到代签退，AGENTS §3.1）。
- 区域读扩展（`visibleReadPlatformIds` 区域∪本班组∪本人）作为附加读谓词保留（偏离 D-A7）。
- **限时授权**：主管发起，起止时间 + 范围 + 权限点，到期自动回收（定时任务），全程审计；不永久扩大默认范围（roles §10 决策 15）。

### 4.5 鉴权链 v2

```
AuthInterceptor（JWT → userId/roles/useUnitId/scopeVersion）
  → RoleCatalog v2（角色 → 部门 + 层级 + 可用端）
  → PermissionMatrix v2（角色 × 71+ 码 → Y/C/-，403）
  → ScopeResolver（6 范围 → 读/写双谓词，越权 1403）
  → 业务归属校验（单据在范围内，否则 403/1403 且不泄露存在性）
```

会话口径：Web 管理端 `session_admin` 与小程序 `session_id` 隔离（V17 不变）；使用单位 Web 登录复用 use_unit 账号体系；**同一端内员工身份与门户身份互斥**（AGENTS §3.9 延伸口径）。

### 6.3 权限驱动

- 路由 `meta.perm` = 新权限码；页面可见 = 页面级码 ≠ `-`；`C` 态只读徽标；直达无权路由 → 403 视图。
- 菜单/按钮级 actions 由 `GET /auth/menus` 下发（扩展现有 MenuService 到新 IA），前端仅保留兜底常量。
- 生产无"角色切换器"：按真实登录角色渲染，多角色走工作台切换（D-A3）。
- 每页页头 meta 显示本页权限码与当前数据范围；禁用按钮 tooltip 注明所需权限码。

## 7. 组件库与视觉（自建，Vue3，无 Element Plus）

以 `UI/admin/` 原型为视觉/交互验收基准（1440×900 优先，兼容 1280）。

- **Token 层**：admin-spec §8 全套 CSS 变量（`--ink #0A0F12` / `--panel #131C21` / `--amber #FFB020` / `--signal #FF4B2B` / `--ok #2FC48D` / `--paper #EDE5D3` 等）+ 新增语义色 + 对比度修正（单据小字 `#5B5341`、角标深字）；正文 13px / 次级 12px / 标签≥11px；数字等宽 `tabular-nums`；系统字体栈，离线零外部请求。
- **壳**：AppShell（侧栏 7+1 组、232↔64px 折叠存 localStorage、顶栏范围指示+用户+退出、面包屑 组/视图/对象、<1024 桌面提示条）。
- **DataTable**：列排序三态（升/降/默认）、关键字搜索、多筛选器、分页 8/16/32、行多选+全选+批量操作条、空态、加载骨架。
- **Drawer**：右侧 560px，元信息条（角色/路由/权限/范围），底部操作按权限渲染。
- **Modal**：危险变体（signal 描边）；二次确认需勾选 checkbox 才可提交。
- **Form**：失焦+提交双校验，错误文案字段下方，必填星号；成功 toast+数据变化+审计。
- **Toast**（成功/警告/错误，3 秒）· **StatusTag**（状态机色映射）· **Timeline**（操作人+角色+时间）。
- **PermButton**：两档门控（§4.3）。
- **四态**：空（筛选 chips+清空）/ 加载（骨架 220ms，分页排序本地瞬时不显示）/ 失败（可读原因+重试+退路，不清空已填数据）/ 403（所需码+允许角色）。
- 移除 Element Plus 与无引用依赖（exceljs），按需构建；组件 vitest 覆盖 + 视图级测试补齐（关闭 docs/12 D-02/D-05）。
