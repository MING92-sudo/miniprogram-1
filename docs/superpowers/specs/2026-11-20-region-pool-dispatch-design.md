# 区域抢单池 + 组织成员管理 设计（2026-11-20）

> 来源：用户 2026-11-20 五条需求 + 两轮确认（区域池全量取代绑定派单；配合人同区域；平台ID 门禁；员工区域在账号管理维护；组织架构可见成员并支持调人）。
> 本文档是施工唯一依据；与 AGENTS §3.1/§3.2/§3.6 现行不变量冲突处以本文档为准，落地时同步修订 AGENTS 并在 `docs/AGENTS-修订记录归档.md` 追加记录。

## 1. 意图与为什么

现状：维保工单按电梯绑定的「主维保/配合人」定向派单，人绑定死在电梯档案上——人请假、离职、区域调整都要逐台改绑定；新装电梯没绑定就无法自动派单；配合人签到和主维保一样被距离围栏拦截（现场常有配合人晚到/从别处赶来的真实场景）；电梯建档没坐标时首个签到者的定位回填后「仅留痕不作围栏」，等于这台梯永远没有围栏。

用户要的实际运作方式：**电梯属于区域，区域里的人都能干；谁到现场谁干；干活的人自己挑搭档；档案坐标从第一次作业自动长出来并从此生效。**

## 3. 实现者自行拍板的默认（用户可否决）

- **M1 认领发生在签到时**，无独立「接单」按钮——用户原话「谁先签到就是谁的主维保」。工单在池里即可被查看详情（电梯/地址/计划时间），到场的第一个主维保签到动作即认领（原子条件更新，后到者报「该工单已被 XX 认领」）。
- **M2 配合人签到仍采集定位留痕**（合规审计与留痕需要），只是不做距离校验、永不因距离拦截；坐标缺失仍 422（与主维保同一采集口径）。签退双人签名要求不变（既有不变量 §3.4）。
- **M3 电梯未设所在区域（「不限区域」）时，其工单池对所有持平台ID的维保员可见**——与档案「未设置=不限区域」语义一致。
- **M4 工单落区域快照列** `work_order.region_id`（派单时取电梯 regionId 快照）：池查询不 join 电梯表，且电梯事后改区域不回溯已在池工单。新增 Flyway V57。
- **M5 配合人签到时校验签到者 = 主维保已选配合人**（动态码仍只绑定工单，但选择配合人后签到端比对 platformId，防「码给错人」冒签）。
- **M6 电梯档案的 workerName/assistantName/workerPlatformId/assistantPlatformId 字段保留在库（历史数据不删）**，但派单/归属链路一律不再读取；管理端「维保人员绑定」区块与「分配电梯」弹窗下线，区域分配用既有「所在区域」字段。
- **M7 无人认领不做超时升级/催办推送**；管理端工单视图与看板能看「待接单」池状态即可（非目标见 §6）。
- **M8 存量在途工单**（PENDING/PROCESSING 且已带人）继续按旧归属跑完（含单人豁免标记）；新工单一律池化。
- **M9 员工无 regionId 时仅可见「不限区域」工单**（并显示补录区域引导）；工单不限区域（region_id 空）时对所有持平台ID的维保员可见（含无区域员工）——消除 builder-check Q2 的交叉矛盾，池谓词收敛为一条：`order.region_id IS NULL OR order.region_id = emp.region_id`。
- **M10 配合人候选与池可见性同用工单的 `region_id` 快照**（不用电梯实时区域），保证「谁能认领」与「能选谁搭档」同一口径；电梯事后改区域不影响在池工单（builder-check Q5）。
- **M11 池参与资格只看「持平台ID + 区域匹配」**，不按角色再限（实际只有维保线人员登记平台ID；LEADER/ADMIN 若持平台ID也可认领，与平台登记口径一致）。
- **M12 「退回池」仅管理端可执行**（`order:dispatch` 权限）：未签到工单直接清空认领回池；已签到未签退工单退回时**原签到/配合人留痕快照写入审计日志后清空**，工单回 PENDING——全程留审计，不留无痕改写。已签退（DONE）工单不可退回。

## 4. 设计

### 4.1 组织架构成员与调人（D1）

- 后端：`GET /org/{id}/members`——返回该节点下员工（班组节点 = `groupName` 匹配，部门节点 = `department` 匹配；单位节点不列员工，使用单位是外部客户租户不进组织树）。权限 `org:view` 读。
- 调人：`PUT /employees/{id}` 扩展接受 `groupName`（目标班组，须存在于组织树 TEAM 节点），权限 `user:edit`；写审计日志（原班组→新班组、操作人）。调人**不影响**区域（regionId 独立维护，D5）。
- 管理端 OrgView：节点详情抽屉增「成员」区块（姓名/手机号/角色/区域），成员行内「调到班组…」下拉 + 确认；改动后树与成员即时刷新。

### 4.2 区域抢单池（D2/D3/D4/M1/M4）

**派单（创建侧）**
- 自动派单（每日 09:00 主扫描 + 13 分钟兜底）与手动派单创建工单时**不再写 workerName/workerPlatformId/assistantName**，改写 `region_id` 快照；状态 PENDING（语义 = 待接单）。「建档即排期」「同项目同日一次性派单」「读接口不触发派单」等既有不变量不变。
- 删除 createOrderIfDue/dispatchNow 中「未绑定主维保不派单/422」守卫（绑定概念取消）；改为无守卫——池化工单天然不需要预绑定。
- 管理端手动派单语义改为「立即发布到区域池」；计划投影（`/admin/plans/projection`）的 `bound` 列改为**区域覆盖提示**（该区域有无持平台ID的维保员，无则标「区域无人」预警）。

**池可见性（读侧）**
- 小程序任务列表分两段：**待接单池**（本区域或未限区域 + PENDING + 未认领，仅对持平台ID的维保员下发）+ **我的工单**（我认领的/我是配合人的）。归属谓词（ScopeResolver/V7 班组谓词）扩展：未认领工单按 `region_id` 放行同区域维保员；已认领工单仍按 主/配合人 谓词。
- 读路径沿用统一响应口径 `{code,message,data}`。

**认领（写侧）**
- 主维保签到 = 认领：`UPDATE work_order SET worker_name=?, worker_platform_id=?, status='PROCESSING' WHERE id=? AND worker_platform_id IS NULL AND status='PENDING'`，受影响行 0 → 1003「该工单已被认领」并回显认领人姓名（与动态码原子消费同一并发防护范式）。
- 认领者必须有 `platformId`（D4）：签到前置校验，无平台ID 422「请先在管理端完成平台人员登记」。
- 认领后原「先签到」语义闭环：工单 worker* 字段从此指向认领人，记录填写人 = 认领人。

**配合人（D3/D4/D8/M5）**
- 新端点 `GET /work-orders/{id}/partner-candidates`：按工单 `region_id` 快照匹配候选人（M10；不限区域时全部）+ 持平台ID + 在职 + 排除主维保本人。
- `POST /work-orders/{id}/assign-partner`（仅主维保本人，配合人未签到前可改选）：落 assistantName/assistantPlatformId。
- 配合人签到：动态码校验消费不变（任何写操作之前），新增「签到者 platformId == 工单 assistantPlatformId」比对（M5），**不做距离校验**（D6），定位照采留痕（M2）。
- **签退门禁（D8）**：未选配合人 / 配合人未签到 / 缺任一方签名 → 422 拦截；双人签名从「有配合人时必填」升级为「恒必填」（存量在途单人豁免标记工单除外，M8）。

### 4.3 签到围栏与坐标回填（D7/D9）

- 主维保围栏逻辑不变（电梯级→品种级→全局三级阈值），**唯一改动：删除 SELF_COLLECTED 免拦截豁免**——回填坐标自回填完成起即为围栏基准；**存量已回填的 SELF_COLLECTED 坐标随发布立即全部生效**（D9，不设过渡期），坐标不准致现场 1001 被拦的由管理端修正电梯坐标。
- 电梯坐标缺失（首次作业）：主维保签到 UNKNOWN 只留痕不拦截 + 回填 SELF_COLLECTED（既有逻辑保留）；配合人在坐标缺失时同样不拦截（本来就免围栏）。
- 回填动作只发生一次（`lng/lat` 已非空不覆盖）。

### 4.4 退回池（D10/M12）

- 新端点 `POST /admin/orders/{id}/release-to-pool`（`order:dispatch` 权限，管理端工单视图行内操作）：校验工单未 DONE → 审计日志记录「退回池 + 操作人 + 原认领人/配合人 + 签到留痕快照」→ 清空 worker/assistant 字段与签到留痕 → 状态回 PENDING（重新入池，region_id 快照不变）。
- 已 DONE 工单不可退回（422）；退回动作幂等（已是未认领 PENDING 时返回 ok 不改状态）。

### 4.4 管理端配套

- 账号管理（UsersView）：开通/编辑表单增「所属区域」下拉（`GET /regions`，可空）；列表增区域列。
- 组织架构（OrgView）：成员列表 + 调人（§4.1）。
- 电梯档案（ElevatorsView）：移除「维保人员绑定」区块；「所在区域」保持必引导（不限区域可空，但空=全员可见，表单注明）。
- 工单视图：PENDING 未认领显示「待接单 · 区域名」，已认领显示认领人；不再展示「计划绑定人」。

### 4.5 小程序配套

- 任务/工作台：待接单池段（区域池），卡片显示电梯/地址/计划时间/超期标签；点击进入详情可导航；签到按钮即认领。
- 签到页：主维保签到成功后引导「选择配合人」（候选下拉，同区域有平台ID）；配合人侧流程不变（动态码），去掉距离拦截提示分支。
- 文案经 `constants/index.js`，错误码复用 1001/1003/422；新错误文案入 TOAST_TEXT。

## 5. 不变量与合规红线（不得破坏）

- 平台 2.6 上报字段口径不变（workMan1Id/workMan2Id 必填 → D4 门禁保证）；签退冻结快照/自动转发/失败只标记人工重报不变。
- 双人动态码 HMAC/5 秒步长/60 秒/一次性消费/先验证后写库，全部不变。
- 工单号只经 OrderNoIssuer；幂等键全写接口携带；openid 只信 jscode2session；签名/照片走既有上传与签名页。
- 客户主体三层收敛、ScopeResolver 写不扩域 等 P1 裁决不受本变更影响。
- 派单仍只由定时任务（+手动发布）创建，读接口一律不触发。

## 6. 非目标 / 反目标

- 非目标：抢单超时自动升级、催接单消息推送、抢单人次数限制、跨区临时调度、区域负责人审批制。
- 反目标：任何形式的无平台ID 上报、伪造/兜底坐标、批量重试入口、把回填坐标标记为人工登记来源。

- 存量电梯绑定字段不再读取但保留；演示种子库（`test-data-all-stages.sql` 等）补员工 regionId 与池化工单样例。

## 8. 验收要点（人工）

- 两台同区域电梯到期 → 池内各出一单；A 签到认领其一，B 再签到同一单被拒并看到认领人；B 签到另一单成功。
- 无平台ID 员工登录：看不到池（或被拦提示语），不能被选为配合人。
- 配合人距电梯 5 公里签到成功（留痕距离），主维保同距离被 1001 拦截（电梯已有坐标）。
- 新梯无坐标：首次主维保签到 UNKNOWN 放行 + 回填；第二次作业 200 米外签到被 1001。
- 组织架构班组节点看到成员，把成员调到另一班组后其工作台/数据域即时生效。
- 未选配合人直接签退被 422；配合人签到+双方签字后签退成功。
- 管理端把已认领工单「退回池」后工单重新出现在池内，审计日志含原认领人与签到留痕快照；DONE 工单退回被 422。

## 9. 实施回写（2026-11-21 收口，实际实现与本设计的差异如实登记）

实现分支 `codex/region-pool`（commits 32a9213…ab951be）。以下为本设计落地时的实际口径与差异：

1. **认领打标 `claimedViaPool`（设计未写，实现新增）**：D8 签退恒双人门禁需要覆盖「不限区域电梯的池化新单」（`regionId` 空但确属新单），单靠 regionId 非空判定不够。实现：主维保签到认领时在 `checkinExtra.claimedViaPool=true` 打标，签退门禁 = `regionId 非空 OR claimedViaPool`；存量工单留痕无此字段 → 走旧口径（M8）。
2. **坐标回填仅限主维保（设计 §4.3 未明确，实现收紧）**：配合人免围栏（D6），其远距定位若回填会污染围栏基线；实现 `!assistant` 才回填 SELF_COLLECTED。D7/D9「存量立即生效、不设豁免」按设计执行。
3. **配合人免围栏的 geoStatus 取值**：实现新增 `ASSISTANT_EXEMPT`（区别于 UNKNOWN/PROVIDED/SELF_COLLECTED），定位照采留痕（M2）、距离照常写入 `assistant_checkin_extra.distance`。
4. **配合人身份比对先于动态码消费（M5 顺序显式化）**：实现注释明确「顺序反了错误人选会吞掉正确人选的码」；存量工单 `assistantPlatformId` 为空时跳过比对（M8 兼容分支，维持原动态码口径）。
5. **电梯读写谓词区域化（超出本设计范围，ab951be）**：绑定取消后「本人负责的电梯」失去载体——读谓词改区域匹配键（不限区域或同区域放行，含非现场岗，读扩写不扩）；写谓词改按**在途工单认领关系**（仅持该梯在途工单的主/配合人或管理角色可改）。
6. **`/admin/plans/projection` 的 `bound` → `regionStaffed`**：按设计 §4.2 执行；不限区域电梯只要有任一持平台ID在职维保员即视为有人。
7. **退回池（D10/M12）实现的两个加固**：①审计 fail-closed——审计服务不可用时 500 禁清库（不同于其它审计点「失败吞异常」口径，本场景审计是清库唯一留证）；②清库条件更新带 `status<>'DONE'` 守卫，并发签退竞态落败整体回滚（含审计）并 422（审查修复 0c15a7c）。**取舍登记**：退回池**保留 `checklistJson`**（清单系签退冻结记录的数据源，重新认领后沿用；如需重置检查项须另行作废工单）、保留 regionId 快照与 planTime；签名 fileId 必须随认领人一并清除（不清则新认领人签退复用旧签名冻结进 2.6 报文=虚假签名）。
