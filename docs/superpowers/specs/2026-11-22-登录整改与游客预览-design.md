# 登录页整改 + 游客预览设计（2026-11-22）

## 意图与背景

提审被驳回两条：

1. 「登录环节，点击取消/返回选项无效」——登录页是 reLaunch 入口页（无返回栈），页面上没有任何"暂不登录"出口；且 `utils/nav.js` 的 `back()` 无栈时 `reLaunch(currentHome())`，未登录会被 guard 弹回登录页形成死循环。违反微信登录规范（用户必须能取消/拒绝登录流程）。
2. 「用户协议、隐私政策点击无响应」——链接是嵌套 `<text>` 内的 `<text catchtap>`，可点击区域小且事件分发在部分机型/基础库不稳定。

用户决策：选方案 B（整改 + 游客预览页），微信一键登录按钮对未绑定用户也显示，走"账号密码登录后自动绑定"流程。

## 目标

- 协议/隐私政策整行可点，e2e 证明可点。
- 登录流程存在可用的取消/返回出口，无死循环。
- 未登录可浏览预览页，登录后照旧进入真实工作台读真实库（登录后链路零改动）。
- 微信一键登录按钮恒显；未绑定微信经账号密码登录后自动绑定。

## 非目标

- 不接官方隐私弹窗（不在本次驳回范围）。
- 预览页不调用任何接口、不展示真实/演示业务数据（纯静态介绍）。
- 不改登录后任何业务链路、不动签到/派单等不变量。
- 不动 `pages/profile` 已有的绑定微信入口。

## 约束

- 小程序端 CommonJS / ES2018 / 单引号 / 2 空格；文案走 `constants/index.js`；遵循 AGENTS §5.4 注释约定。
- 接口改动两处同步：`services/` + `mock/server.js`。
- 登录页路由保持入口页形态（reLaunch 目标不变），改动不破坏现有 e2e 用例。

## 改动清单

### 1. `pages/login/index`（wxml + js）

- 协议行重构：勾选框与协议链接分行；`<view class="lg-agree" bindtap="openAgreement">`、`<view bindtap="openPrivacy">` 整行可点区块，替代嵌套 text catchtap。点击仍要求先勾选吗？——否：看协议不要求勾选，勾选只与登录/微信登录提交相关（现状如此，保持不变）。
- 「暂不登录，先随便看看」入口 → `wx.navigateTo('/pages/preview/index')`（保留栈，返回键自然回登录页）。
- 微信一键登录按钮恒显（移除 `wechatBound` 显隐判断；`em_wechat_bound` 存储仍由 profile 绑定写入，登录页不再读取做显隐）。
- 未绑定流程：`onWechatLogin` 捕获 422 → toast「该微信未绑定账号，请使用账号密码登录，登录后将自动绑定」→ 记录 `this._pendingBindCode = code`；`onSubmit` 账号密码登录成功后，若 `this._pendingBindCode` 存在则 `await auth.bindWeChat(code)`：成功 → 写 `em_wechat_bound=true`；失败（code 过期/一次性失效）→ 静默忽略，toast 提示「微信绑定未成功，可稍后在「我的」中绑定」；无论成败继续正常 `enterApp`。

### 2. `utils/nav.js`

- `back()` 无栈分支先看登录态：未登录 → `reLaunch('/pages/preview/index')`；已登录 → `currentHome()`。消除返回死循环。

### 3. 新页面 `pages/preview/index`（4 个文件 + app.json 注册 + routes.js `auth: false`）

- 内容（全部静态，文案入 `constants` 的 `PREVIEW_TEXT`）：品牌区；功能模块卡片（维保计划、工单执行、签到签退、电子签名、监管上报、移交查验）；作业流程示意（签到 → 清单 → 签退 → 双人签字 → 上报）；获取账号指引（账号由维保单位管理员开通）+ 客服联系方式（复用 `BRAND`）。
- 顶部导航「登录」按钮 → `nav.open('/pages/login/index')`；页面可下拉/点返回回登录页。

### 4. `mock/server.js`

- `POST /auth/wx-login` 增加未绑定分支：`body.code === 'UNBOUND'` 时抛 `{ code: 422, message: '该微信尚未绑定账号，请先用账号密码登录并绑定微信' }`，与后端 `AuthController.wxLogin` 一致（其余 code 行为不变）。

### 5. e2e（`scripts/e2e`）

- 新增用例：登录页点《用户协议》→ 页面栈进入 agreement；点返回回登录页；点「暂不登录」→ 预览页 → 返回登录页；wx-login 传 `code:'UNBOUND'` → 422 提示 → 账号密码登录 → 触发 `/auth/bind-wechat`。
- 沿用现有 cases.*.js 的结构与断言方式，跑 `node scripts/e2e/run.js` 验证。

### 6. 自检

- 根目录 `npm run lint`；新增/改动用例全绿。

## 交给实现者的决定（已确认）

- 预览页内容：纯静态介绍（无接口、无真实数据）。
- 微信登录按钮文案、位置保持不变，仅改显隐逻辑。
