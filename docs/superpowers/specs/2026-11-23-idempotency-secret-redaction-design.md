# 幂等响应口令脱敏设计

## 目的与原因

当前人员建档、人员重置密码和客户账号开通会把 `initialPassword` 随完整响应写入 `idempotency_key.response_json`，完成记录又可永久重放，违背一次性展示和不落库明文的契约。本阶段阻止新增明文并清理存量幂等响应。

## 目标

- 首次业务响应保持现状，仍可向合法操作者展示一次初始口令。
- 幂等层持久化前递归移除所有对象中的 `initialPassword`、`password` 字段，数组内对象同样处理。
- 同键重放返回脱敏后的其余业务字段，不返回口令，不重新执行业务。
- 追加 Flyway `V69` 清理既有响应，不删除幂等键。

## 非目标与约束

- 不修改账号口令、不自动重置或轮换口令；存量口令是否轮换另作运维处置。
- 不改变业务表、接口路径或首次响应结构。
- 不处理跨层事务、键作用域、过期接管、签字或签退恢复；这些按既定顺序进入后续阶段。
- 不执行真实监管写接口，不操作生产数据库。

## 方案比较

- **采用：幂等层统一脱敏 + V69 存量清理。** 在 `IdempotencyService.Guard.commit` 将结果转为 Jackson 树，递归移除口令字段后序列化；控制器仍返回原始结果。集中实现可覆盖当前及未来同类响应。
- **未采用：控制器分别构造安全响应。** 只覆盖已知入口，字段与重放逻辑分散，后续容易漏掉。

## 存量迁移口径

- V69 使用 Flyway Java 迁移与 Jackson 语义解析；有效 JSON 递归删除所有层级的 `initialPassword`、`password`，保留其他字段，包括 Unicode 转义的字段名。
- 对无法解析且含目标字段名的响应，将响应替换为 `{"redacted":true}`；检测前解码 Unicode 转义，并按字段名加冒号识别，避免误伤仅含相同文本的普通值。
- 不匹配口令字段的记录不变，所有幂等键保留。

## 验收

- 首次响应中的口令不变；传给 mapper 的幂等 JSON 不含口令且保留其他字段，原始结果对象未被修改。
- 嵌套对象和数组中的口令同样被移除。
- 重放不返回口令，不调用业务。
- 真实 MySQL 中先迁移至 V68 并插入有效、嵌套、无效及无口令样本，再迁移至 V69：有效记录仅移除目标字段，无效敏感记录变为安全标记，无口令记录不变，所有键保留。
- `mvn -f backend/pom.xml test` 全量通过；真实 MySQL 未执行时不得声称迁移验收完成。
