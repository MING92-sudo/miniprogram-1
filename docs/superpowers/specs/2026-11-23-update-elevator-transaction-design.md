# updateElevator 两写事务设计

## 目的

修复电梯更新先 `updateById`、再显式清坐标/区域/状态时第二写失败留下半成品的问题。

## 方案

在 `AdminArchiveService.updateElevator` 增加 `@Transactional`，保持写入顺序、校验、接口和响应不变。合并 SQL 或重写 Wrapper 属于不必要重构，不采用。

## 范围

仅修改该方法及其测试。不处理其他档案方法、删除并发、幂等核心或外部副作用。

## 验收

- 事务代理测试中，显式清 NULL 第二写抛错时 rollback 且不 commit。
- 真实 MySQL 中同时修改名称并清坐标，第二写注入失败后名称、坐标均保持原值。
- 正常清坐标与更新行为不变，后端全量测试通过。
- 开发期无真实数据；仅使用随机隔离数据库，不操作生产数据。
